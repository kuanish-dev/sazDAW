# Plugin delay compensation (PDC)

A plugin with lookahead (a limiter, a linear-phase EQ) outputs audio later than it received it. Without compensation, parallel paths (a limiter on one bus, nothing on another) would drift apart — "flamming".

* **Contract.** `Effect::latency_samples` and `Instrument::latency_samples` (`daw-contracts`, default 0): the latency in frames, valid after `prepare`, may change after `prepare` and after parameter changes; the call is cheap and made from the audio thread. A VST3 effect and a VST3 instrument read `getLatencySamples` in `prepare` and return the stored value (see the limitations below). The total for everyone else is `EngineStats::latency()` → `EngineLatency { frames, sample_rate }` (`seconds()`); clamping is counted in `EngineLosses::latency_clamped`.
* **Where and when it is computed.** `daw-engine/src/mixer/latency.rs` (`GraphMixer::align_latency`, called by `Engine::apply_snapshot`) — on the audio side on every snapshot application (any edit, a DSP object arriving/leaving; after `prepare` the snapshot is applied again), not on every block. We walk the snapshot's topological order: a node's input = the maximum of the outputs of all its sources, **including sidechain** (the compressor key arrives aligned with the main input); output = input + the node's own latency (an instrument, an enabled effect, and the lead of a channel whose time alignment is set earlier — see "Channel utility" ([docs/features/channel-utility.md](channel-utility.md)); 0 otherwise, and always 0 for the master). A connection whose audio arrives earlier than that maximum is delayed by the difference. The master's input is the total latency `L`: all timeline audio in the master sounds exactly `L` later than the transport position.
* **Built-in effects with latency:** the linear-phase EQ (`linear_eq`, a block plus half its kernel: 6,144 frames at 48 kHz, see "Built-in effects" ([crates/daw-effects/CLAUDE.md](../../crates/daw-effects/CLAUDE.md))); the other built-in effects run without lookahead and report 0.
* **A bypassed effect** adds no latency: it does not process audio, and bypassing is a new snapshot after which compensation is recomputed (a short jump when toggling is a deliberate price for simplicity).
* **Delay lines** (`mixer/delay.rs`, `DelayLines`): a pool of `MAX_DELAY_LINES` = 32 rings of `MAX_PDC_FRAMES` = 32,768 stereo frames (~0.68 s at 48 kHz; the limit is in frames because memory is allocated before the sample rate is known) — 8 MB per engine, written at creation. A line is bound to a connection (from, to, sidechain), so edits that do not change that connection do not cut the audio in it; changing the delay amount of the same connection keeps the contents and crossfades from the old delay to the new one over one segment (so nudging a channel earlier moves every other path without a click), and a new connection gets a cleared line. A delay above the limit is clamped to it, and a connection without a free line goes without delay — both cases are counted in `EngineLosses::latency_clamped` (once per snapshot application), and the watcher thread logs any increase (`source: "engine"`). No allocations or locks in the audio thread: the `arrival`/`output` tables live in the preallocated `Scratch`.
* **Timeline and position.** Sources are not shifted earlier (that would require looking ahead through notes and clips); the approach is a uniformly delayed master and a shifted display. `daw-rpc/src/telemetry.rs` reports the **heard** position in `tick.positionTicks` (during playback — the transport position minus `L`, converted to ticks via the tempo map, no less than 0) and `L` in milliseconds in `tick.latencyMs`; the transport panel shows "PDC N ms" next to CPU only if `latencyMs > 0` (the mock sends 0). The metronome and other post-processors receive the segment time shifted by `L` (`Engine::heard`), so the click lands in time with the delayed music (the metronome does not play beats "before zero"). Recorded live notes also get their timing minus `L`: the musician plays to what they hear. Audio recording (`daw-audio-recorder`) trims the recording latency **plus** `L` from the start of the take (`take.rs: save_takes`): a manually entered recording latency stays the device latency, and PDC is added automatically.
* **Limitations.** Sample preview bypasses the graph and is not delayed. A VST3 plugin's latency is read only in `prepare` (the host does not listen to `restartComponent(kLatencyChanged)` yet): a later change is picked up when the plugin is prepared again (a device change or a re-created instance), not on the next edit. In a loop, metronome clicks in the last `L` before the loop end do not sound.
* **Adding something similar** (e.g. the latency of external hardware on a node): a node's own latency is a branch in `GraphMixer::own_latency` (the channel lead is one); tests — `daw-engine/src/tests/latency.rs` (the stub effect `Latent` with real latency).
