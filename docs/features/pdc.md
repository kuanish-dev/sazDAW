# Plugin delay compensation (PDC)

A plugin with lookahead (a limiter, a linear-phase EQ) outputs audio later than it received it. Without compensation, parallel paths (a limiter on one bus, nothing on another) would drift apart — "flamming".

* **Contract.** `Effect::latency_samples` and `Instrument::latency_samples` (`daw-contracts`, default 0): valid after `prepare`, may change after `prepare` and parameter changes, called from the audio thread (cheap, no allocations or locks). A VST3 effect and instrument read `getLatencySamples` in `prepare` and return the stored value (see the limitations below). The total for everyone else is `EngineStats::latency()` → `EngineLatency`; clamping is counted in `EngineLosses::latency_clamped`.
* **Where and when it is computed.** `daw-engine/src/mixer/latency.rs` (`GraphMixer::align_latency`, called by `Engine::apply_snapshot`) — on the audio side on every snapshot application (any edit, a DSP object arriving/leaving; after `prepare` the snapshot is applied again), not on every block. A node's input is aligned to the latest of all its inputs, **including sidechain** (the compressor key arrives aligned with the main input); its own latency comes from an instrument, an enabled effect, or the lead of a channel whose time alignment is set earlier (see "Channel utility" ([docs/features/channel-utility.md](channel-utility.md))). Connections are delayed, not nodes. The master's input is the total latency `L`: all timeline audio in the master sounds exactly `L` later than the transport position.
* **Built-in effects with latency:** only the linear-phase EQ (`linear_eq`, see "Built-in effects" ([crates/daw-effects/CLAUDE.md](../../crates/daw-effects/CLAUDE.md))); the others run without lookahead and report 0.
* **A bypassed effect** adds no latency: it does not process audio, and bypassing is a new snapshot after which compensation is recomputed (a short jump when toggling is a deliberate price for simplicity).
* **Delay lines** (`mixer/delay.rs`, `DelayLines`): a preallocated pool of `MAX_DELAY_LINES` rings of `MAX_PDC_FRAMES`. A line is bound to a connection (from, to, sidechain), so edits that do not change that connection do not cut the audio in it; a new delay on the same connection crossfades over one segment (so nudging a channel earlier moves every other path without a click). A delay above the limit is clamped, and a connection without a free line goes without delay — both counted in `EngineLosses::latency_clamped`, and the watcher thread logs any increase (`source: "engine"`). No allocations or locks in the audio thread: the tables live in the preallocated `Scratch`.
* **Timeline and position.** Sources are not shifted earlier (that would require looking ahead through notes and clips); the approach is a uniformly delayed master and a shifted display. `daw-rpc/src/telemetry.rs` reports the **heard** position in `tick.positionTicks` (during playback the transport position minus `L`) and `L` in `tick.latencyMs`; the status bar (`ui/shell/StatusBar.tsx`) shows "PDC N ms" next to CPU only while it is above 0 (the mock sends 0). The metronome and other post-processors receive the segment time shifted by `L` (`Engine::heard`), so the click lands in time with the delayed music. Recorded live notes also get their timing minus `L`: the musician plays to what they hear. Audio recording (`daw-audio-recorder`, `take.rs: save_takes`) trims the recording latency **plus** `L` from the start of the take: a manually entered recording latency stays the device latency, and PDC is added automatically.
* **Limitations.** Sample preview bypasses the graph and is not delayed. A VST3 plugin's latency is read only in `prepare` (the host does not listen to `restartComponent(kLatencyChanged)` yet): a later change is picked up when the plugin is prepared again (a device change or a re-created instance), not on the next edit. In a loop, metronome clicks in the last `L` before the loop end do not sound.
* **Adding something similar** (e.g. the latency of external hardware on a node): a node's own latency is a branch in `GraphMixer::own_latency` (the channel lead is one); tests — `daw-engine/src/tests/latency.rs` (the stub effect `Latent` with real latency).
