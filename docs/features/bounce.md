# Rendering a track to audio (bounce, freeze)

**Contracts** (`daw-contracts/src/bounce.rs`): `TrackRender` — "the sound of one track on its own" (`render_track(project, track, tail) → TrackSound { start_tick, data }`) and `TrackBounce` — "replace a track with its sound" (`bounce`, `freeze`, `unfreeze`); the freeze mark is `InstrumentSpec::frozen: Option<TrackId>` (id of the audio copy), the "sounding" instrument is `Track::sounding_instrument()` (`None` for a frozen one). The track's sound path is `Graph::insert_path` (the same convention as the mixer's `domain/mixerStrips.ts`: the first regular connection is "post-fader", an insert is an effect with nothing else feeding into it; sends do not break the path).

* **What the copy contains.** In this graph the source fader sits BEFORE the inserts (a compressor on the track hears the sound after the track volume), so "pre-fader" would sound different here. Copy = the sound at the output of the track's path: instrument (or audio clips) → track volume and pan (with automation) → inserts (with their automation and the levels of the connections between them). Track mute/solo, the output connection, sends, buses and the master are not included; sidechain inputs of inserts are silent. The copy gets volume 1 and pan 0 and goes to the same place at the same level as the track's path did (`set_output` + `connect`), so the project sounds as before. Sends are not transferred to the copy.
* **Render** (`daw-render/src/track.rs`, `TrackRender for OfflineExporter`): `isolate` builds a project containing only this track, its clips, the nodes of its path and the master at unity (a pure function with tests); the range is from the start of the first clip to the end of the last plus the tail (`check_tail`: `0..=MAX_TAIL_SECONDS`, the same rule as the export tail; 2 s by default); 48 kHz stereo, in memory (at most 20 minutes). The engine is the same offline instance as for export (`load_engine`, seeked to the start of the first clip).
* **Placement** (`daw-project/src/bounce.rs`, `ProjectBounce`): rendering happens BEFORE the undo group (the project is not locked while the sound is computed) → WAV (`SampleWriter`) into the project's `samples/` named "<track> (audio)" / "(freeze)" (`AssetStore::new_asset_path`) → undo group: import the sample (`SampleCatalog`), an audio track (`TrackControl::add_track` + `move_track` right below the source), a clip at the position of the first clip (`ClipControl::add_audio_clip`), volume and output of the copy (`GraphControl`); then `bounce` mutes the source (node mute), while `freeze` writes the freeze mark through the core. Failure — `cancel_group` (the WAV stays in `samples/`). `unfreeze` is one group: remove the copy (`remove_track`) and its samples if they do not play anywhere else, clear the mark; if the copy was deleted manually, only the mark is cleared. A project without a file, no clips, a frozen track (for `bounce`/`freeze`), an audio track (for `freeze`) — rejected with a clear message.
* **Freezing in the engine.** DSP reconciliation (`service/sync.rs`) and offline rendering create an instrument only for `sounding_instrument()`: a frozen instrument is removed from the engine (less load), its notes are silent. `TrackControl::set_instrument` on a frozen track is rejected ("unfreeze first"): the copy sounds with the previous instrument. Templates clear the freeze mark.
* **RPC:** `tracks.bounce { id, tailSeconds? }` → id of the copy, `tracks.freeze { id, tailSeconds? }` → id of the copy, `tracks.unfreeze { id }` (`daw-rpc/src/bounce.rs`). These methods (like `presets.save`, `templates.save`, `project.export` and `analysis.*`) are registered with `add_flushing`: before them, open plugin windows hand their state to the project (`PluginStateFlush`).
* **Interface:** the track menu on right-click on the header (`ui/tracks/TrackMenu.tsx`, "Audio" section): "Bounce to audio", "❄ Freeze" / "Unfreeze"; a frozen track shows ❄ in its header. Actions — `actions/bounce.ts` (a loading indicator while rendering, errors as a toast, the copy is selected after success). Mock — `mock/handlers/bounce.ts` (creates a sample of the right length and a clip; the copy's output is always the master).
* **Limitations.** Latency of insert plugins (PDC) is not compensated in the copy: the copy's sound is late by the inserts' latency (0 for built-in effects). The WAV is 24-bit: sound above 0 dBFS is clipped. Sends and automation of the output connection are not transferred. The sound is computed entirely in memory.
* **Tests:** `isolate` and the range — `daw-render/src/track.rs`; `Graph::insert_path` — `daw-contracts/src/graph/tests.rs`; the `TrackBounce` contract (copy position, output, volume, mute, one undo step, rejections, freeze/unfreeze and DSP) — `daw-project/src/tests/bounce.rs` (render double); full session with the built-in synth — `daw-bootstrap/tests/render_bounce.rs` (the copy's WAV = the track's sound in the mix; the mix after bounce, after freeze and after unfreeze sounds as before); wire — `daw-rpc/tests/arrangement.rs`.
* **Similar** (e.g. "bounce the selected range"): the range is a `TrackRender` parameter, placement is the same `ProjectBounce::place`.
