# Rendering a track to audio (bounce, freeze)

**Contracts** (`daw-contracts/src/bounce.rs`): `TrackRender` — "the sound of one track on its own" (`render_track`) and `TrackBounce` — "replace a track with its sound" (`bounce`, `freeze`, `unfreeze`); the freeze mark is `InstrumentSpec::frozen` (id of the audio copy), the "sounding" instrument is `Track::sounding_instrument()` (`None` for a frozen one). The track's sound path is `Graph::insert_path` (the same convention as the mixer's `mixer/mixerStrips.ts`: the first regular connection is "post-fader", an insert is an effect with nothing else feeding into it; sends do not break the path).

* **What the copy contains.** In this graph the source fader sits BEFORE the inserts (a compressor on the track hears the sound after the track volume), so "pre-fader" would sound different here. Copy = the sound at the output of the track's path: instrument (or audio clips) → track volume and pan (with automation) → inserts (with their automation and the levels of the connections between them). Track mute/solo, the output connection, sends, buses and the master are not included; sidechain inputs of inserts are silent. The copy plays at unity and goes to the same place at the same level as the track's path did, so the project sounds as before.
* **Render** (`daw-render/src/track.rs`, `TrackRender for OfflineExporter`): `isolate` builds a project containing only this track's path and the master at unity (a pure function with tests); the range is from the first clip to the end of the last plus the tail (`check_tail`, the same rule as the export tail); rendered in memory by the same offline engine as export (`load_engine`).
* **Placement** (`daw-project/src/bounce.rs`, `ProjectBounce`): rendering happens BEFORE the undo group (the project is not locked while the sound is computed) → WAV (`SampleWriter`) into the project's `samples/` (`AssetStore::new_asset_path`, named "<track> (audio)" / "(frozen)") → one undo group through the other entities (`SampleCatalog`, `TrackControl`, `ClipControl`, `GraphControl`): the sample, an audio track right below the source, a clip at the first clip's position, the copy's volume and output (`place`); then `bounce` mutes the source node, while `freeze` writes the freeze mark through the core. Failure — `cancel_group` (the WAV stays in `samples/`). `unfreeze` is one group: remove the copy and its samples if they do not play anywhere else, clear the mark; if the copy was deleted manually, only the mark is cleared. A project without a file, no clips, a frozen track, an audio track (for `freeze`) — rejected.
* **Freezing in the engine.** DSP reconciliation (`service/sync.rs`) and offline rendering create an instrument only for `sounding_instrument()`: a frozen instrument is removed from the engine (less load), its notes are silent. `TrackControl::set_instrument` on a frozen track is rejected ("unfreeze first"): the copy sounds with the previous instrument. Templates clear the freeze mark.
* **RPC** (`daw-rpc/src/bounce.rs`): `tracks.bounce`, `tracks.freeze` (→ id of the copy), `tracks.unfreeze`. `bounce` and `freeze` (like `project.save`, `presets.save`, `templates.save`, `project.export` and `analysis.*`) are registered with `add_flushing`: before them, open plugin windows hand their state to the project (`PluginStateFlush`).
* **Interface:** the track header's right-click menu (`tracks/TrackMenu.tsx`, "Audio" section): "Bounce to audio", "Freeze" / "Unfreeze"; a frozen track shows ❄ in its header. Actions — `tracks/bounce.ts`. Mock — `mock/handlers/bounce.ts` (no sound; the copy's output is always the master).
* **Limitations.** Latency of insert plugins (PDC) is not compensated in the copy: the copy's sound is late by the inserts' latency (0 for built-in effects). The WAV is 24-bit: sound above 0 dBFS is clipped. Sends and automation of the output connection are not transferred. The sound is computed entirely in memory (hence the length limit `MAX_BOUNCE_SECONDS`).
* **Tests:** `isolate` and the range — `daw-render/src/track.rs`; `Graph::insert_path` — `daw-contracts/src/graph/tests.rs`; the `TrackBounce` contract (render double) — `daw-project/src/tests/bounce.rs`; the full session with the built-in synth (the copy's WAV = the track's sound in the mix; the mix sounds as before after bounce, freeze and unfreeze) — `daw-bootstrap/tests/all/render_bounce.rs`; wire — `daw-rpc/tests/all/arrangement.rs`.
* **Similar** (e.g. "bounce the selected range"): the range is a `TrackRender` parameter, placement is the same `ProjectBounce::place`.
