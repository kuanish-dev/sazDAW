# Audio clip editing: fades, gain, trim, normalize, reverse

**Fades.** `Clip { fade_in_ticks, fade_out_ticks, fade_in_shape, fade_out_shape }`; `FadeShape { Linear, EqualPower, SCurve, Exponential }` with one formula `FadeShape::gain(progress)` (`daw-contracts/src/clips.rs`, allocation-free) that the engine applies per frame (`audio_voices.rs: fade_at`, on top of the equal-power crossfades), so export sounds the same; the frontend draws the curves with the same formulas (`domain/fades.ts: fadeGain`). Shapes are set by `ClipEdit { fade_in_shape, fade_out_shape }`; fade lengths are clamped to the clip length (no other cap). A new shape: add the variant and its formula in both places.

**Trimming the start.** `ClipControl::trim_start(id, tick)` (RPC `clips.trimStart`): the left edge moves, the end stays, the content stays in place — an audio clip's `offset_frames` moves by the frames those ticks play (`Clip::ticks_to_source_frames`), stopping at the file start; a note clip's `offset_ticks` turns around its loop; the comp shifts (`take_rules::shift_comp`, also used by split). Pure rule: `clip_rules.rs: trim_start`; the frontend preview and the mock share `domain/clips.ts: trimmedClip`.

**Normalize and reverse** (`ClipProcessing`, `daw-project/src/clip_processing.rs`). Two roles split by rule 8: the clip side decides what changes (gain; which sample and offset), the sample editor does the audio work through its contract — `SampleEditor::peak(id, from, to)` measures, `SampleEditor::reverse_copy(id)` writes a reversed WAV into the project folder and imports it (needs a saved project, `samples::REVERSE_NEEDS_SAVED_PROJECT`). `normalize(ids, peak_db)` is non-destructive: the peak of the source frames each clip plays (all takes, from `offset_frames` for the clip length) sets `gain = 10^(peak_db/20) / peak`, capped at `MAX_CLIP_GAIN` (silent clips keep their gain), one edit. `reverse(id)` points the clip at the reversed copy with the mirrored offset (`total − (offset + played)`), so the same piece plays backwards in place; it is a history group (import + clip edit), cancelled on failure; clips with several takes are refused (`clips::REVERSE_NEEDS_ONE_TAKE`). RPC: `clips.normalize { ids, peakDb? }` (default −0.3 dBFS), `clips.reverse { id }`. Mock: `mock/handlers/clips.ts` (normalize assumes a fixed peak).

**Timeline UI.** `timelineRender.ts: drawAudioHandles` draws the fade curves (shaded above the curve), fade handles on the top edge where each fade ends, and the gain line (when selected or not at 0 dB); geometry and hit-testing are in `timelineLayout.ts` (`audioZoneAt`, `gainLineY`, `draggedGain`, `trimStartAt`). `timelinePointer.ts`: drag a fade handle (grid-snapped, `domain/fades.ts: fadeLengthAt`), drag the gain line (dB tooltip, Shift — fine), drag the left edge (trim, `actions.clips.trimStart` with the drawn `trimmedClip`, shown until the backend replies); edits are drawn as `ClipDraft.edited` and committed once on release. Right-click on an audio clip opens `ClipMenu.tsx` (Normalize — the selection if the clip is in it, Reverse, fade shapes, Delete; on a fade — only that fade's shapes); right-click on a note clip still deletes it. The toolbar gain slider goes to `MAX_CLIP_GAIN` (×4).
