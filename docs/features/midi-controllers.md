# MIDI controllers: pitch bend, CC, aftertouch and MIDI learn

Performance expression (pitch wheel, modulation wheel, pedal, pressure) reaches instruments from clips, from a MIDI keyboard and from MIDI files; controller knobs can be assigned to any project parameter.

* **Model** (`daw-contracts/src/model.rs`): `NoteContent::controllers` — `ControllerLane { kind: ControllerKind, points }`, at most one lane per kind; `ControllerKind::range` gives the allowed values. Point times are from the content start and repeat with the content, like notes. **Between points the value holds as a step:** that is how MIDI messages behave, and dense points give smoothness — simpler, and the same for the engine, files and drawing.
* **Editing** — `NoteControl::set_controller_lane` (`daw-contracts/src/notes.rs`, its doc lists the checks and errors; rule — `daw-project/src/note_rules.rs`): replaces a lane, empty points remove it, one undo step. Auto length counts points (`fit_length`); a manual length drops points beyond it. RPC `notes.setControllerLane`. Tests — `daw-project/src/tests/controllers.rs`; wire — `daw-contracts` (`controller_lanes_use_the_exact_wire…`) and `daw-rpc/tests/all/controllers.rs`.
* **Instruments.** `Instrument::controller(kind, value)` is a required method, so every built-in states what it does: the sampler — pitch bend and the CC64 pedal; the synth (`daw-synth`) — pitch bend and CC1 opening the filter; drums and strings ignore controllers. Live: `LiveNoteSink::controller`, RPC `live.controller`.
* **Engine** (`daw-engine/src/controllers.rs`: `ControllerSchedule`, preallocated, no allocations). `play_events` in `engine.rs` plays instruments in chunks between note **and** controller events; a controller on the same tick goes before the note, so bend and pedal already affect it. **Chase:** after start, seek and loop wrap (`Plan::release_all` while playing) the schedule adds the value that holds at the new position, so jumping into the middle of a bend sounds like playing from the start. **Reset:** on every `release_all` (stop, pause, seek) `InstrumentRack::reset_controllers` sets to 0 only those of pitch bend, aftertouch, CC1 and CC64 (`RESETTABLE`) that the instrument received since the last reset — like "Reset All Controllers"; other CCs (e.g. volume CC7) are left alone, and a plugin gets no extra messages. Tests — `daw-engine/src/tests/controllers.rs`.
* **VST3** (`daw-vst3/src/midi_map.rs`: `MidiAssignments`; plugin calls — `instance/midi.rs`). In VST3 controllers are not events but parameters the plugin names through `IMidiMapping`; the table is built when the instrument is created, and `Vst3Instrument::controller` puts the change into the same `PendingChanges` queue as parameters. Offset 0 is exact because the engine plays the instrument in chunks between events. A controller the plugin does not listen to is dropped and counted in `BlockFaults`. Real-plugin test — `daw-vst3/tests/all/synth.rs: pitch_bend_reaches_the_synth_through_its_midi_mapping` (skipped if the test synth is not built).
* **Live input** (`daw-midi/src/input.rs`): `route` sends notes and controllers to the track's instrument, but a CC is first offered to `MidiMappingControl::control_change` — a consumed one (learning or an assignment) does not reach the instrument; CC 120–127 never do. Value conversion — `values.rs`, shared with files.
* **Recording** (`daw-recorder/src/controllers.rs`: `ControllerTake`). The engine hands played controllers to the recorder (`RecordedEvent` with `LiveMessage::Controller`); the track's first event binds the take clip as a note does (`ensure_bound`). Points go into the take clip's lane with `set_controller_lane` inside the "Recording" group. The dense stream is thinned (`MIN_STEP`, `MIN_GAP_SECONDS`; the last knob position is never lost); loop passes replace earlier points as for notes.
* **MIDI files** (`daw-midi/src/file/`): clip export writes points as they are, project export unrolls repeats. Import into a clip takes the controllers from the same file track as the notes and replaces the notes and **all** lanes in one undo step — that is why `MidiFiles` holds `HistoryControl` (the "Import MIDI" group, failure — `cancel_group`).
* **MIDI learn** — `MidiMappingControl` (`daw-contracts/src/midi.rs`), implementation `ProjectMidiMappings` (`daw-project/src/midi_mappings.rs`), wiring — `daw-bootstrap/src/wiring/project.rs` (`wiring/audio.rs` hands it to `MidiInputService`).
  * Assignments live **in the project** (`Project::midi_mappings`): targets are ids of this project's nodes, tracks and parameters, meaningless in another project, so they are saved and undone with it. Targets are the same as for automation and checked by the same `ops::validate_target`. Learning (`learn`) is armed in memory, not in the project.
  * The next CC creates the assignment (undo step "Assign MIDI controller"); the parameter range is copied from the catalog into `min`/`max`, so turning the knob never consults the catalogs.
  * An assigned CC sets the parameter **like a knob in the interface** — through its owner (`GraphControl`, `TrackControl`, `StageControl`), an undo step merged with neighbouring moves; right before that it is reported to the automation writer (`AutomationWriter::touch` with `TouchEnd::Idle`: a knob has no release), which writes it only in Touch/Latch while playing (see [automation.md](automation.md)). The value is linear `min..max` (volume is the linear level, not the fader curve).
  * An assignment to a vanished target has no effect and is not shown; undoing the deletion brings it back; "Clear project" removes assignments.
  * RPC `midi.learn`, `midi.cancelLearn`, `midi.mappings` (→ mappings and the target being learned), `midi.removeMapping`. Tests — `daw-project/src/tests/midi_mappings.rs`, `daw-rpc/tests/all/controllers.rs`.
* **Frontend.** Types — `api/types/model.ts`; actions — `midi/midiLearn.ts`: `mappings()` comes from the project copy, filtered by `automation/automationRules.ts: targetExists` (the mirror of `validate_target`); `learning()` is re-read from the backend after `learn` and, while waiting, on every project change, because a turned knob ends learning with an edit. The right-click menu of every parameter control is `common/ParamMenu.tsx` (automation lane: add/show — `automation/automation.ts: showFor` — and delete; MIDI: assign, remove, stop waiting); the sample picker of `ParamControl` has none. The list of assignments — "Settings" → "MIDI" (`settings/MidiSection.tsx`). Mock (`mock/handlers/midi.ts`): there is no knob, so `midi.learn` assigns the first free CC at once.
* **Adding something similar** (e.g. polyphonic pressure): a `ControllerKind` variant and its `range`, parsing in `input.rs` and `file/read.rs`, writing in `file/write.rs`, the VST3 number in `midi_map.rs`, tests at every layer; frontend — the kind in `pianoroll/controllers.ts`.
