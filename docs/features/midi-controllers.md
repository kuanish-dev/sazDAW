# MIDI controllers: pitch bend, CC, aftertouch and MIDI learn

Performance expression (pitch wheel, modulation wheel, pedal, pressure) reaches instruments from clips, from a MIDI keyboard and from MIDI files; controller knobs can be assigned to any project parameter.

* **Model** (`daw-contracts/src/model.rs`). `NoteContent::controllers: Vec<ControllerLane>` (JSON `controllers`, not written when empty), at most one lane per kind. `ControllerLane { kind: ControllerKind, points: Vec<ControllerPoint { tick, value }> }`; `ControllerKind` — `{ "type": "cc", "number": 0..=119 }` | `{ "type": "pitchBend" }` | `{ "type": "aftertouch" }` (channel pressure); `range()` — `-1..=1` for pitch bend (0 is the center), `0..=1` for the rest; `CC_MODULATION` = 1, `CC_SUSTAIN` = 64, `MAX_CC_NUMBER` = 119 (120–127 are channel mode messages). Point times are from the start of the clip content, as for notes; lanes repeat with the content (`loop_ticks`). **Between points the value holds as a step** (no smooth transition): this is how MIDI messages themselves behave, and smoothness comes from dense points — simpler and identical for the engine, files and drawing.
* **Editing** — `NoteControl::set_controller_lane(clip, kind, points)` (`daw-contracts/src/notes.rs`; rule — `daw-project/src/note_rules.rs: set_controller_lane`): replace or create a lane, empty points — remove it; sorted by tick, among duplicates the last one wins; a CC number above 119 or a tick past the content (with auto length — past `MAX_CLIP_LOOP_TICKS`) — `OutOfRange`, a value outside `range` — `Invalid`, more than `MAX_CONTROLLER_POINTS` (4096) — `LimitReached`; one undo step. Auto length takes points into account (`fit_length`), a manual length drops points beyond it. RPC `notes.setControllerLane { clip, kind, points }`; tests — `daw-project/src/tests/controllers.rs`, wire — `daw-contracts` (`controller_lanes_use_the_exact_wire…`) and `daw-rpc/tests/controllers.rs`.
* **Instruments.** `Instrument::controller(kind, value)` is a required method (built-ins implement it explicitly): the sampler — pitch bend ±2 semitones (speed of all voices) and the CC64 pedal (voices released while the pedal is down fade out when the pedal is released); drums do nothing (a hit plays to its end on its own). `LiveNoteSink::controller(track, kind, value)` — the same live (the value is clamped to `range`); RPC `live.controller`.
* **Engine** (`daw-engine/src/controllers.rs`: `ControllerSchedule`, capacity 8192, no allocations). Lane points of note clips within the segment's tick window (repeats and phase as for notes); `play_events` in `engine.rs` plays instruments in chunks between note **and** controller events (a controller on the same tick goes before the note: bend and pedal already affect it). **Chase:** after start, seek and loop wrap (`Plan::release_all` while playing), the schedule adds at the start of the segment the value that holds at the new position (the last point strictly before it inside the clip — accounting for repeats and phase), so jumping into the middle of a bend sounds like playing from the start. **Reset:** on every `release_all` (stop, pause, seek) `InstrumentRack::reset_controllers` sets to 0 those of pitch bend, aftertouch, CC1 and CC64 that the instrument received since the previous reset (like "Reset All Controllers"; other CCs, e.g. volume CC7, are left alone; untouched ones are not sent — the plugin gets no extra messages). Tests — `daw-engine/src/tests/controllers.rs` (exact frame, order relative to notes, chase, reset, loop).
* **VST3** (`daw-vst3/src/midi_map.rs`: `MidiAssignments`; plugin calls — `instance/midi.rs`). In VST3, controllers are not events but parameters that the plugin names through `IMidiMapping::getMidiControllerAssignment(bus 0, channel 0, number)` (CC 0..119, `kAfterTouch` = 128, `kPitchBend` = 129). The table is built when the instrument is created; `Vst3Instrument::controller` puts the parameter change (pitch bend `-1..1` → `0..1`) into the same `PendingChanges` queue as parameters; offset 0 is exact because the engine plays the instrument in chunks between events. If the plugin does not listen to a controller, the change is dropped and counted in `BlockFaults` ("MIDI controllers the plugin does not listen to"). A real plugin is checked by `tests/synth.rs: pitch_bend_reaches_the_synth_through_its_midi_mapping` (note frequency from zero crossings: 440 → 493.9 Hz; the test is skipped if the synth is not built).
* **Built-in synth** (`daw-synth`): pitch bend ±2 semitones (`Engine::set_pitch_bend`), the CC1 modulation wheel opens the filter up to 4 octaves above the high cut (`set_modulation`); `prepare`/`reset` return the wheels to rest; other controllers are ignored.
* **Live input** (`daw-midi/src/input.rs`): `parse_message` parses notes, CC, pitch bend (14-bit) and channel pressure; `route` sends notes and controllers to the track's instrument, but a CC is first offered to `MidiMappingControl::control_change` — a consumed one (learning or an assignment) does not go to the instrument; CC 120–127 do not go to instruments. Value conversion — `values.rs` (14-bit: 0 → −1, 8192 → 0, 16383 → exactly 1; 7-bit: n/127) — shared with files.
* **Recording** (`daw-recorder/src/controllers.rs`: `ControllerTake`). The engine hands played controllers to the recorder (`RecordedEvent { track, message: LiveMessage::Note | Controller, tick }`); the track's first event binds the take clip the same way a note does (`ensure_bound`). Points are written into the take clip's lane with `set_controller_lane` (in the same "Record" group). **Thinning:** a point is kept only if the value changed by more than 1/127 or more than 10 ms have passed since the last kept one (seconds — per the tempo map); a small frequent change is deferred and kept at the end of the take — the last knob position is not lost; identical consecutive values are not written. The span recorded in a loop pass replaces the lane points that were in it before the take; the next pass replaces what was recorded in the previous ones (as for notes).
* **MIDI files** (`daw-midi/src/file/`): clip export — points as they are, project export — with repeats unrolled (a track with only controllers is written too); on one tick: note-offs, controllers, note-ons. Import into a clip takes the controllers from the same file track as the notes, drops consecutive repeated values and replaces the notes and **all** lanes of the clip in one undo step (`MidiFiles` holds `HistoryControl`: the "Import MIDI" group, failure — `cancel_group`).
* **MIDI learn** — `MidiMappingControl` (`daw-contracts/src/midi.rs`), implementation `ProjectMidiMappings` (`daw-project/src/midi_mappings.rs`), wiring — `daw-bootstrap/src/wiring/project.rs` (`MidiInputService` gets it too). Assignments live **in the project** — `Project::midi_mappings: [{ cc, channel?, target: ParamTarget, min?, max? }]` (JSON `midiMappings`): the target is nodes, tracks and parameters of this project; their ids mean something else in another project; assignments are saved and undone together with the project. Targets are the same as for automation and are checked by the same rule `ops::validate_target`. `learn(target)` arms learning (in memory, not in the project); the next CC creates an assignment (the channel is the one it came from; the parameter range comes from the catalog and is remembered in `min`/`max`, so knob movement does not go to the catalogs; a previous assignment of the target is replaced; undo step "Assign MIDI controller"). An incoming assigned CC sets the parameter **like a knob in the interface** — through the owners (`GraphControl::set_volume/set_pan/set_effect_param/connect`, `TrackControl::set_instrument_param`): an undo step merged with neighboring movements; **right before that it is reported to the automation writer** (`AutomationWriter::touch` with `TouchEnd::Idle`: a knob has no release), which writes it only in Touch/Latch mode while playing (see "Automation: editing and live writing" ([docs/features/automation.md](automation.md))). The value is linear `min..max` (volume is the linear level `0..1.5`, not the fader curve). An assignment to a vanished target has no effect and is not shown; undoing the target's deletion brings it back; "Clear project" removes assignments. RPC: `midi.learn { target }`, `midi.cancelLearn`, `midi.mappings` → `{ mappings, learning }`, `midi.removeMapping { target }`. Tests — `daw-project/src/tests/midi_mappings.rs`, `daw-rpc/tests/controllers.rs`.
* **Frontend.** Types — `api/types/model.ts` (`ControllerKind`, `ControllerLane`, `MidiMapping`, `MidiMappings`), calls — `api.midi.learn/cancelLearn/mappings/removeMapping`, actions — `actions/midiLearn.ts` (`learn` with the hint "Turn a knob…"; `mappings()` is read from the project copy, without assignments to vanished targets — `domain/automation.ts: targetExists`, the backend's `validate_target`; `learning()` is read from the backend after `learn` and, while waiting, on every project change, because a turned knob ends learning with an edit). Right-click on a knob or fader — `ui/common/ParamMenu.tsx` (the parameter's context menu: "Add / Show automation" (creates the lane if needed, shows it under the timeline and switches to Tracks — `actions/automation.ts: showFor`; the shown lane is UI state `session.selection.automation()`), "Delete automation", then "Assign MIDI controller" / "Remove assignment (CC n)" / "Stop waiting for a knob"); the automation header lists the project's lanes as chips (click shows one) instead of a picker; it is used on `ParamControl` (effect and instrument parameters, except sample choice), `PanKnob`, the width knob of `ChannelUtility`, volume faders (`Inspector`, `NodeStrip`, `ChannelStrip`) and the volume knob in the track header. The list — "Settings" → "MIDI" → "Knobs on parameters" (the same `mappings()`). Mock (`mock/handlers/midi.ts`): there is no knob, so `midi.learn` immediately assigns the first free CC starting from 20.
* **Adding something similar** (e.g. polyphonic pressure): a `ControllerKind` variant and its `range`, parsing in `input.rs` and `read.rs`, writing in `write.rs`, the VST3 number in `midi_map.rs`, tests at every layer; frontend — the kind in `domain/controllers.ts`.
