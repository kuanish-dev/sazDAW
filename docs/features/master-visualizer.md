# Master visualizer

**Master visualizer** (spectrum and oscilloscope on the master strip, `ui/mixer/MasterVisualizer.tsx`). Contract: `EngineStats::watch_master(on)` and `master_window() → MasterWindow { samples, sample_rate }` (`daw-contracts/src/engine.rs`; `MASTER_WINDOW_FRAMES` = 2048 mono frames, oldest first, empty while not watched). Engine: `daw-engine/src/scope.rs: MasterScope` in `Telemetry` — a preallocated ring of atomics that the audio thread fills in `process_segment` after the preview voice (before the ±1 clamp and the metronome: the picture shows the music, not the clicks), only while watched; the control side copies it out (a read racing a write may mix two segments — harmless for a picture, and the audio thread stays lock-free). RPC `audio.watchMaster { on }` / `audio.masterWindow` (`daw-rpc/src/audio.rs`), actions `audio.watchMaster` / `audio.masterWindow`, mock `mock/liveSound.ts` (synthesized "music" at the mock transport position, as loud as the mock master meter). The component turns capture on while it is shown, polls ~30 times per second and turns it off when the mixer closes (`state/poller.ts: createWatchedPoll`); the math — a Hann-windowed FFT, log-spaced bands from 30 Hz to 16 kHz on a dB scale, an oscilloscope start at a rising zero crossing so a steady tone stands still — is the pure `domain/visualizer.ts`. There is one switch for the app: a second visualizer would need a watcher count in `MasterScope`.
