# Preferences: the user's and the app's

**User preferences (backend).** The role is "remember the user's preferences": the `PreferencesStore` contract (`get`/`set`) and the `Preferences` type (`daw-contracts/src/preferences.rs`: `{ language, profile: { author, projectsFolder, openLastProject }, autosaveSeconds, appearance: { theme, accent, uiScale, trackHeight, showHints } }`; defaults come from `Default`, limits are the constants `MIN/MAX_AUTOSAVE_SECONDS`, `MIN/MAX_UI_SCALE`, `MAX_AUTHOR_CHARS`; validation and normalization are in `Preferences::checked`, shared by all implementations). The implementation is `PreferencesFile` (`daw-persistence/src/preferences.rs`, `preferences.json` in the state folder, on top of `JsonState`): no file — defaults; a corrupted file or out-of-range values — defaults and a log entry (`persist`); `set` validates, writes atomically (`JsonState::try_persist`: on failure — a system-kind (`4`) error code, the previous value stays in memory) and returns what was saved. It lives in `Controls.preferences`; it is read by autosave (the interval) and `MidiFiles` (author → Copyright event on `exportClip`/`exportProject`). The backend only stores the appearance settings. "Open last project" (on by default) is honored at startup: `Startup::open` in `daw-bootstrap` opens nothing when the setting is off. RPC: `preferences.get`, `preferences.set { preferences }` (`daw-rpc/src/preferences.rs`). A new setting: a field in `Preferences` (+ a default and validation in `checked`) → a contract test → the reader receives `Arc<dyn PreferencesStore>` in `daw-bootstrap`.

**App preferences** (RPC `preferences.get`/`preferences.set`, the `Preferences` type — `api/types/preferences.ts`; defaults, limits and choices — `domain/preferences.ts`, whose limits the mock `mock/handlers/preferences.ts` checks with the backend's codes). The interface copy is a signal in `state/preferences.ts`, read via `session.preferences()`; only `actions/preferences.ts` changes it, via `ctx.showPreferences`: `update(change)` shows the new value immediately, saves it on the backend and shows what was saved; a rejection means a toast and a rollback. Loading happens in `createSession` before the first project read, so project dialogs already know the projects folder (the backend opens the last project at startup, see "User preferences") (`actions/project.ts`: a new project goes into the projects folder; open/save as — next to the current one, otherwise in the projects folder, otherwise "Documents"). Appearance is applied by `state/appearance.ts`: theme ("system" follows `prefers-color-scheme` live) and accent are the `data-theme`/`data-accent` attributes on the root (accent colors are in `index.css`), `ui/common/theme.ts: palette()` notices their change (`MutationObserver`), and canvases redraw; theme and accent are cached in `localStorage` only to avoid a flash before the preferences arrive (`applyCachedLook` in `index.tsx`). Zoom is `AppShell.setZoom` (Tauri: `getCurrentWebview().setZoom`, permission `core:webview:allow-set-webview-zoom` in `src-tauri/capabilities/default.json`; browser: CSS `zoom`). Track row height is `session.appearance.rowHeight()` — the default for rows; a track can have its own (see "Track row heights" ([app/src/ui/tracks/CLAUDE.md](../../app/src/ui/tracks/CLAUDE.md))).
