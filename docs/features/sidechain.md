# Sidechain, gain reduction and effect graphs

* **Picking the key.** `GraphControl::set_sidechain(effect, source: Option<NodeId>)` (RPC `graph.setSidechain { effect, source | null }`, one undo step): replaces every sidechain edge into the effect (and their lanes) with `source → effect` and sets the effect's `sidechain` param to match. An effect reads its key only if its catalog has a `sidechain` param (compressor, gate, dynamic EQ) — other kinds are `graph::NO_SIDECHAIN_INPUT`; a source the graph rules reject is their code. Implementation `daw-project/src/graph.rs`, mock `mock/handlers/graph.ts`; tests `daw-project/src/tests/sidechain.rs`, RPC wire `daw-rpc/tests/all/graph.rs`. UI: `effects/SidechainPicker.tsx` (candidates `graph/graphRules.ts: sidechainCandidates`) in the effect panel; dragging a wire to the card's sidechain port in the graph works too.
* **Gain reduction and band gains** — what a dynamic effect is doing right now, for its meter and graph. `Effect::gain_reduction_db() -> Option<f32>` (compressor, gate, limiter, multiband compressor, de-esser) and `Effect::band_gains_db() -> &[f32]` (band-split effects: the multiband compressor's reduction per band, the dynamic EQ's moving gains; at most `MAX_EFFECT_BANDS`). The mixer asks after each `process` and writes into a fixed atomic slot per effect-store position (`daw-engine/src/meters.rs: report_reduction`, `report_bands`; no allocations or locks); `EngineStats::gain_reductions` / `band_gains` return the extreme value since the last read, and only effects processed since then (a bypassed one drops out). Telemetry sends `reductions` and `bands` in the tick (`daw-rpc/src/telemetry.rs`). Frontend: reductions are kept with decay in `mixer/levels.ts: createReductions` (`session.mixer.reductions`); band gains are held for a moment and let back toward 0 dB by `effects/bandGainRules.ts` and `effects/bandGains.ts: createBandGains`. The mock fakes both (`mock/meters.ts: mockReductions`, `mockBandGains`). Tests: `daw-engine/src/tests/processors.rs`, per effect in `daw-effects`.
* **Effect panel** (`effects/EffectPanel.tsx`, used by the graph inspector and the mixer popover): generic controls for every param (`ParamControl`) plus, by effect kind, a live graph above them (`EffectGraph.tsx`, also used by the signal path view). Dragging a graph handle goes through `graph.setEffectParam` like a knob. Which graph each kind gets, the live sound behind them and how to add one: "Live effect visuals" ([app/src/effects/CLAUDE.md](../../app/src/effects/CLAUDE.md)). The graphs' math is pure and **mirrors** the Rust DSP (`effects/biquad.ts` ↔ `biquad.rs`, `eqCurve.ts` ↔ `eq.rs`, `compressorCurve.ts` ↔ `dynamics.rs: GainComputer::reduction`, and one module per other effect) — change both sides together.
