# Sidechain, gain reduction and effect graphs

* **Picking the key.** `GraphControl::set_sidechain(effect, source: Option<NodeId>)` (RPC `graph.setSidechain { effect, source | null }`, one undo step): removes every sidechain edge into the effect (with their lanes), connects `source → effect` as a sidechain at level 1 and sets the effect's `sidechain` param to 1 (`None` → 0). An effect reads its key only if its catalog has a `sidechain` param (compressor, gate, dynamic EQ) — other kinds are `graph::NO_SIDECHAIN_INPUT` (GR-122); a source the graph rules reject is their code. Implementation `daw-project/src/graph.rs`, mock `mock/handlers/graph.ts`; tests `daw-project/src/tests/sidechain.rs`, RPC wire `daw-rpc/tests/all/graph.rs`. UI: `ui/effects/SidechainPicker.tsx` ("Sidechain from: none / tracks and buses", candidates `domain/graph.ts: sidechainCandidates`) replaces the bare switch in the effect panel; dragging a wire to the card's sidechain port in the graph still works.
* **Band gains.** A band-split effect also says what each band is doing: `Effect::band_gains_db() -> &[f32]` (default empty; at most `MAX_EFFECT_BANDS` = 4, lowest band first, dB: negative a cut, positive a boost — the multiband compressor's reduction per band, the dynamic EQ's moving gains). The mixer reports them after each `process` into a fixed slot per effect-store position next to the reduction (`meters.rs: report_bands`; per band the deepest cut and the highest boost are two atomics, because `fetch_max` on f32 bits orders only non-negative values; no alloc/locks); `EngineStats::band_gains` → `BandGains { node, db }` returns per band the value farthest from 0 dB since the last read (a bypassed effect drops out). Telemetry sends `bands: [{ node, db: [..] }]` in the tick; the graphs hold each reading for a moment and let it back toward 0 dB (`domain/bandGains.ts`, `ui/effects/bandGains.ts: createBandGains`); the mock fakes them (`mock/meters.ts: mockBandGains`). Tests: `daw-engine/src/tests/processors.rs`, per effect in `daw-effects`.
* **Gain reduction meter.** `Effect::gain_reduction_db() -> Option<f32>` (default `None`; compressor, gate, limiter, multiband compressor, de-esser report it). The mixer asks after each `process` and writes it into a fixed atomic slot per effect-store position (`daw-engine/src/meters.rs: report_reduction`, no alloc/locks); `EngineStats::gain_reductions` takes the deepest value since the last read (only effects processed since then — a bypassed one drops out). Telemetry sends `reductions: [{ node, db }]` in the tick (`daw-rpc/src/telemetry.rs`); the frontend keeps them with decay (`state/levels.ts: createReductions`, `session.reductions`), the mock fakes them (`mock/meters.ts: mockReductions`). Tests: `daw-engine/src/tests/processors.rs`, per effect in `daw-effects`.
* **Effect panel** (`ui/effects/EffectPanel.tsx`, used by the graph inspector and the mixer popover): generic controls for every param (`ParamControl`) plus, by effect kind, a live graph above them (`EffectGraph.tsx`, also used by the signal path view) — `eq` → `EqGraph.tsx` (response curve 20 Hz–20 kHz, ±18 dB, draggable band handles: drag = frequency/gain, wheel on the mid band = Q, double-click = reset; changes go through `graph.setEffectParam` like a knob), `filter` → `FilterGraph.tsx` (one handle: cutoff and resonance), both over the live spectrum (`LiveSpectrum.tsx`); `compressor`/`limiter`/`gate` → `DynamicsGraph.tsx` (transfer curve, level/GR history, GR meter, gate state); `distortion`/`saturator`/`tape` → `ShaperGraph.tsx`; `delay` → `DelayGraph.tsx`; `chorus` → `ChorusGraph.tsx`; `reverb` → `ReverbGraph.tsx`; `multiband` → `MultibandGraph.tsx` (band split, live response, reduction per band, split handles, solo/bypass chips); `dynamic_eq` → `DynamicEqGraph.tsx` (full-gain and live response, band handles); `de_esser` → `DeEsserGraph.tsx` (detection band, live response, GR meter); `transient` → `TransientGraph.tsx` (a model hit shaped by the knobs, live input/output envelopes); `linear_eq` → `LinearEqGraph.tsx` (the EQ's graph with its latency noted) — see "Live effect visuals" ([app/src/ui/effects/CLAUDE.md](../../app/src/ui/effects/CLAUDE.md)). The math is pure and **mirrors** the Rust DSP (`domain/biquad.ts` ↔ `biquad.rs`, `eqCurve.ts` ↔ `eq.rs`, `compressorCurve.ts` ↔ `dynamics.rs: GainComputer::reduction`, and one module per other effect) — change both sides together. A graph for another effect: a pure domain module from its param convention (like `domain/envelope.ts` for instruments) and a `Match` in `EffectGraph`.
* **EQ bands** (`eq.rs`): low cut (12 dB/oct Butterworth high-pass, `low_cut` 20…1000 Hz, off at 20 Hz), low shelf, peaking mid (with Q), high shelf, high cut (low-pass, `high_cut` 1…20 kHz, off at 20 kHz). "Off at the extreme" keeps a new EQ transparent without extra switches.
