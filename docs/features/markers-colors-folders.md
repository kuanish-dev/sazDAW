# Song markers, track colors and folders

**Model** (`daw-contracts/src/model.rs`): `Project.markers`, `Project.folders`, `Track.color`, `Track.folder`. A color is a name from the closed palette `TRACK_COLORS` (checked by `check_color`, `daw-contracts/src/tracks.rs`); the on-screen shade is chosen by the interface (`common/trackColors.ts`). A track without its own color is colored by its number in the project, not its row, so collapsing a folder does not recolor it.

- **Contracts.** `MarkerControl` (`daw-contracts/src/markers.rs`, "where each section begins"), `FolderControl` (`daw-contracts/src/folders.rs`, "which tracks are shown together"), `TrackControl::set_color`. A folder is only a view: folder mute/solo set the flag on the source nodes of all its tracks in one undo step — an honest substitute for a "folder bus", since a folder does not change the sound or the graph. Every edit is one undo step.
- **Why membership is stored on the track, not as a list in the folder.** This way a track cannot end up in two folders, and a deleted track leaves nothing dangling. The rule "a folder's tracks stand together at the topmost of them, an empty folder is deleted" is kept by one function, `daw-project/src/folder_rules.rs: gather`, called by `move_track`, `remove_track` and all folder edits. Therefore `move_track` does not change membership: a folder track moved down returns to its block, and one moved above the folder lifts the whole folder.
- **RPC** (`daw-rpc/src/markers.rs`, `folders.rs`, `tracks.rs`): `markers.add`/`edit`/`remove`, `tracks.setColor`, `folders.create`/`edit`/`remove`/`setTracks`/`setMute`/`setSolo`. The descriptions are written for an AI that marks up a song; the MCP instructions mention `markers_add` and `folders_create`. Tests: `daw-project/src/tests/markers.rs`, `folders.rs`; `daw-rpc/tests/all/arrangement.rs`.
- **Frontend.** Actions: `tracks/markers.ts` (`Markers`), `tracks/folders.ts` (`Folders`), `tracks.setColor`. List rows come from the pure `tracks/trackRows.ts`: `trackRows` (a folder row above its tracks), `lanesOf` (timeline rows, `null` for a folder row — so row hit-testing, group moves, area selection and sound drops work by rows without knowing about folders), `summaryRowOf` (clips of hidden tracks are drawn as a strip on the folder row), `planTrackDrop` (where a dragged track lands; leaving a folder for another place is two undo steps). They are shared by `TracksView`, `Timeline`, `timelineRender`, `timelinePointer`, `timelineDrop`; `TracksView` renders headers with `Index`, not `For`, because rows are rebuilt on every edit and `For` would re-create headers in the middle of a knob drag.
  Headers: `FolderHeader.tsx` (folder M/S lit when every track has the flag — `tracks/trackRows.ts: folderFlags`); `TrackHeader` has a color stripe, color and folders are in its right-click menu (`TrackMenu.tsx`; shared `common/ContextMenu.tsx`, `ColorSwatches.tsx`), with no new header buttons. A mixer strip shows the track color on top.
  Markers: flags on the ruler and a line across the rows — `markerRender.ts`, geometry `markerLayout.ts`, mouse `markerPointer.ts` (it gets ruler events before the clip pointer; gestures are listed at its top). "＋ Marker" on the timeline panel adds a marker at the bar of the position; ⌥← / ⌥→ jump between markers (`shell/globalKeys.ts`). Mock: `mock/handlers/markers.ts`, `mock/handlers/folders.ts`, rules `mock/folderRules.ts`.
- **Limitations.** Taking a track out of a folder by dragging is two undo steps; a whole folder is moved by its top track (the folder row has no handle of its own); markers have no color.
- **Something similar** (e.g. marker color): a field in the model → contract and test → RPC → mock → action → menu.
