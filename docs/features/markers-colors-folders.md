# Song markers, track colors and folders

**Song markers, track colors and folders.** Model (`daw-contracts/src/model.rs`): `Project.markers: Vec<Marker { id, tick, name }>` (always sorted by tick) and `Project.folders: Vec<Folder { id, name, collapsed, color? }>` (both `#[serde(default)]`); a track has `Track.color: Option<String>` and `Track.folder: Option<FolderId>`. A color is a name from the closed palette `TRACK_COLORS` (12 names, `check_color` in `tracks.rs`); the on-screen shade is chosen by the interface (`ui/common/trackColors.ts`: `trackColorOf`, `clipColorOf`); a track without its own color is colored by its number in the project (not its row — that doesn't change when folders collapse), audio clips by a shared color.
- **Contracts.** `MarkerControl` (`markers.rs`, "where each section begins"): add/edit/remove; one marker per tick, an empty name or one longer than `MAX_MARKER_NAME` — `Invalid`, a tick beyond `MAX_CLIP_TICK` — `OutOfRange`, more than `MAX_MARKERS` — `LimitReached`. `FolderControl` (`folders.rs`, "which tracks are shown together"): create, edit (`FolderEdit`: name, collapsed, color; `null` removes the color), remove (tracks stay in place), `set_folder_tracks` (membership and order as a whole), `set_folder_mute`/`set_folder_solo` (a flag on the source nodes of all its tracks in one undo step — an honest substitute for a "folder bus": a folder does not change the sound or the graph). `TrackControl::set_color`. Every edit is one undo step.
- **Why membership is stored on the track, not as a list in the folder.** This way a track cannot end up in two folders, and a deleted track leaves nothing dangling. The order inside a folder is the order of `tracks`; the rule "a folder's tracks stand together at the topmost of them, an empty folder is deleted" is enforced by a single function, `folder_rules::gather`, called by `move_track`, `remove_track` and all folder edits. Therefore `move_track` does not change membership: a folder track moved down returns to its block, and one moved above the folder lifts the whole folder.
- **RPC** (`daw-rpc/src/markers.rs`, `folders.rs`, `tracks.rs`): `markers.add {tick, name}` → id, `markers.edit {id, tick?, name?}`, `markers.remove {id}`; `tracks.setColor {id, color|null}`; `folders.create {name, tracks}` → id, `folders.edit {id, name?, collapsed?, color?}`, `folders.remove {id}`, `folders.setTracks {id, tracks}`, `folders.setMute/setSolo {id, on}`. The descriptions are written for an AI that marks up a song; the MCP instructions contain a line about `markers_add` and `folders_create`. Tests: `daw-project/src/tests/markers.rs`, `folders.rs`; `daw-rpc/tests/arrangement.rs`.
- **Frontend.** Actions: `actions/markers.ts` (`MarkersActions`: add, addAtPlayhead, move, rename, remove, jump), `actions/folders.ts` (`FoldersActions`: create, edit, remove, place, moveInto, takeOut, setMute/setSolo), `tracks.setColor`. List rows come from the pure `domain/trackRows.ts`: `trackRows` (a folder row above its tracks; a collapsed folder hides them), `lanesOf` (timeline rows: a track, or `null` for a folder row — so `rowAt`, `clampRow`, `moveGroup`, `clipsInArea` and sound drops work by rows without knowing about folders), `summaryRowOf` (clips of hidden tracks are drawn as a strip on the folder row), `planTrackDrop` (drag gap → folder and index: a gap inside an expanded folder puts the track into it with a single `folders.setTracks`, a gap outside — `tracks.move`; a track leaving a folder first exits it — two undo steps). They are shared by `TracksView` (headers via `Index`: rows are rebuilt on every edit, and `For` would re-create headers in the middle of a knob drag), `Timeline`, `timelineRender`, `timelinePointer`, `timelineDrop`. Headers: `FolderHeader.tsx` (▸/▾, name, track count, folder M/S — lit when every track has the flag, `domain/trackRows.ts: folderFlags`; right-click — color, "Rename", "Remove folder"); `TrackHeader` has a color stripe on the left, color and folders are in the right-click menu (`TrackMenu.tsx`; shared `ui/common/ContextMenu.tsx` and `ColorSwatches.tsx`), with no new buttons in the header. A mixer strip shows the track color as a stripe on top. Markers: flags in the lower half of the ruler and a line across the rows — `markerRender.ts` (separate from the bar numbers and time signature flags), geometry — `markerLayout.ts`, mouse — `markerPointer.ts` (gets ruler events before the clip pointer: click — move the position to the marker, drag — move by bars, double-click — edit the name in a field on the flag, right-click — delete, Alt + double-click on an empty part of the ruler — new marker). "＋ Marker" on the timeline panel places a marker at the bar of the position; ⌥← / ⌥→ jump to the neighboring marker (table in `state/globalKeys.ts`, shown in "Keyboard shortcuts"). Mock: `mock/handlers/markers.ts`, `mock/handlers/folders.ts`, rules — `mock/folderRules.ts`.
- **Limitations.** Markers snap to a 4/4 bar (`BAR_TICKS`, as with clip insertion); taking a track out of a folder by dragging is two undo steps; a whole folder is moved by its top track (the folder row has no handle of its own); markers have no color. Something similar (e.g. marker color): a field in the model → contract and test → RPC → mock → action → menu.
