# Song loop

- **Where and why.** In the transport clock (`daw-transport`), by the same mechanism as the loop region: the segment is cut at the end and the position jumps on the exact frame, and the engine sees an ordinary jump (notes are released, `playback.rs`). A frontend watcher that seeks back would be late by up to a tick (~33 ms) and audible. One rule decides what playback wraps around — `Shared::wrap_region`: the loop region wins; otherwise `(0, song end)` while the song loop is on, not held and the arrangement is not empty. The clock and the control side read the same rule. Playback already at or past the end runs on (as with the loop region), so starting after the last clip to add a new part works.
- **Contract** (`TransportControl`, `daw-contracts/src/transport.rs`): `set_song_loop(on)` / `song_loop()` — the mode, on by default; it belongs to the running app and is not saved (no project or preferences field). The metronome switch, by contrast, is remembered between launches in its own small store (`MetronomeSettingsStore`, `metronome.json`), not in `Preferences`, so the settings page and the transport button never overwrite each other's copy. `set_song_end(Option<u64>)` — set by the project in `ProjectService::sync` (`daw-project/src/service/sync.rs`, next to `set_loop`) on every edit, undo included. `hold_song_loop(bool)` — a recording asks playback to run straight on (a counted hold: each recorder pairs its calls). `wrap_region()` — what playback wraps around now; `BlockTiming::loop_region` carries it to plugins.
- **Song end** — `Project::song_end` (`daw-contracts/src/model.rs`): the tick after the last note or audio clip. Automation clips do not count (no sound of their own). The export's "whole song", the level analysis and the project summary use the same method. The loop point is `Project::song_loop_end`: the song end rounded up to a whole bar of the tempo map, so the looped song keeps its beat.
- **Recording.** A jump back at the song end under a take would cut it, so recording holds the song loop: armed note recording (`daw-recorder`, `RecordControl::set_armed`; an `AtomicBool` swap pairs the hold with one release) and a running audio take (`daw-audio-recorder`, from `start` to `stop`, a failed start or drop). The loop region still wraps while recording: notes loop inside their clip, audio passes become takes (see "Loop recording" ([docs/features/recording.md](recording.md))).
- **Offline engines** (export, bounce, analysis) build their own transport, which never receives a song end, so they never loop.
- **RPC/MCP:** `transport.setSongLoop { enabled }` (`daw-rpc/src/transport.rs`); the tick telemetry has `songLoop` and `wrap` (what playback wraps around now; it replaced the old `loop` field, which only fed the cursor).
- **UI.** The loop button (`IconLoop`) on the transport bar (`ui/transport/TransportBar.tsx`, next to the metronome) calls `TransportActions.setSongLoop`; strings `project.transport.songLoop`/`songLoopHint` (EN + RU). The smooth cursor (`domain/playhead.ts`) stops at the end of `tick.wrap` until the jump arrives. Mock — `mock/songLoop.ts` (`wrapRegion`, the same rule; armed note recording and an audio take hold it), `MockWorld.songLoop`/`recordingAudio`, `transport.setSongLoop` in `mock/handlers/transport.ts`.
- **Tests:** the clock — `daw-transport/src/lib.rs` (frame-accurate jump, loop region priority, off/empty song, past the end, holds); the song end — `daw-contracts/src/model.rs`; project → transport — `daw-project/src/tests/clips.rs`; the recorders' holds — `daw-recorder/src/tests.rs`, `daw-audio-recorder/src/tests/lifecycle.rs`; RPC and telemetry — `daw-rpc/tests/all/tempo.rs`; by ear in a full session — `daw-bootstrap/tests/all/render_playback.rs`. A session test that checks silence after the song turns the song loop off.
