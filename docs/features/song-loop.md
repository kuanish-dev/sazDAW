# Song loop

- **Where and why.** In the transport clock (`daw-transport`), by the same mechanism as the loop region: the segment is cut at the end and the position jumps on the exact frame, and the engine sees an ordinary jump (notes are released, `daw-engine/src/playback.rs`). A frontend watcher that seeks back would be late by up to a tick (~33 ms) and audible. One rule decides what playback wraps around — `Shared::wrap_region` (the loop region wins, then the song); the clock and the control side read the same rule. Playback already at or past the end runs on, so starting after the last clip to add a new part works.
- **Contract** (`TransportControl`, `daw-contracts/src/transport.rs`): `set_song_loop`/`song_loop`, `set_song_end`, `hold_song_loop`, `wrap_region`; `BlockTiming::loop_region` carries the wrap to plugins. The mode belongs to the running app and is not saved (no project or preferences field). The metronome switch, by contrast, is remembered in its own store (`MetronomeSettingsStore`), not in `Preferences`, so the settings page and the transport button never overwrite each other's copy. The song end is pushed by the project in `ProjectService::sync` (`daw-project/src/service/sync.rs`, next to `set_loop`) on every edit, undo included.
- **Song end** — `Project::song_end` (`daw-contracts/src/model.rs`); export's "whole song", the level analysis and the project summary use the same method. The loop point is `Project::song_loop_end`: rounded up to a whole bar of the tempo map, so the looped song keeps its beat.
- **Recording.** A jump back at the song end under a take would cut it, so recording holds the song loop: armed note recording (`daw-recorder`, `RecordControl::set_armed`) and a running audio take (`daw-audio-recorder`, from start to stop, a failed start or drop). The loop region still wraps while recording: notes loop inside their clip, audio passes become takes (see "Loop recording" in [recording.md](recording.md)).
- **Offline engines** (export, bounce, analysis) build their own transport, which never receives a song end, so they never loop.
- **RPC/MCP:** `transport.setSongLoop` (`daw-rpc/src/transport.rs`); the tick telemetry has `songLoop` and `wrap` (what playback wraps around now).
- **UI.** The loop button on the transport bar (`transport/TransportBar.tsx`) calls `Transport.setSongLoop`. The smooth cursor (`core/playhead.ts`) stops at the end of `tick.wrap` until the jump arrives. Mock — `mock/songLoop.ts` (`wrapRegion`, the same rule; recordings hold it), `MockWorld.songLoop`/`recordingAudio`, `mock/handlers/transport.ts`.
- **Tests:** the clock — `daw-transport/src/lib.rs`; the song end — `daw-contracts/src/model.rs`; project → transport — `daw-project/src/tests/clips.rs`; the recorders' holds — `daw-recorder/src/tests.rs`, `daw-audio-recorder/src/tests/lifecycle.rs`; RPC and telemetry — `daw-rpc/tests/all/tempo.rs`; by ear in a full session — `daw-bootstrap/tests/all/render_playback.rs`. A session test that checks silence after the song turns the song loop off.
- **Something similar** (e.g. jumping back to the cue instead of bar 1): change `Shared::wrap_region` and its contract doc, the mock's `wrapRegion`, and a clock test.
