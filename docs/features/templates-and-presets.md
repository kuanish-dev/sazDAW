# Project templates and presets

Both jobs live in the application state folder (not in the project) and are implemented in `daw-persistence`; the contracts and shared name rules (`check_preset_name`: no `/ \ :`, control characters or leading dot, up to 64 characters) are in `daw-contracts/src/presets.rs`; on the frontend the same rules are in `domain/presets.ts`.

* **Templates** (`ProjectTemplates`, `TemplateFolder`, `templates.rs`): a template is a small project folder `<state>/templates/<name>/template.dawproj` + `samples/`, written by the same `ProjectStorage` as a project (copying sounds and relative paths work on their own). It includes the structure: tracks with instruments (parameters and plugin state), colors and folders, the graph (effects, buses, connections, faders), the tempo map. Removed: clips, automation, loop, markers and samples, except sampler sounds (parameters of kind `ParamKind::Sample` — per the catalog, `structure_of`); the freeze mark is cleared. `create_project(template, file)`: the template is read, gets the file's name, is written into a new folder (sounds are copied) and opened with `ProjectIo::load`. RPC: `templates.list`, `templates.save { name }`, `templates.remove { name }`, `project.createFromTemplate { path, template }` (`daw-rpc/src/templates.rs`). Interface: the `ui/transport/TemplatesDialog.tsx` window — from the project menu ("New from template…", "Save as template…") and from the welcome screen ("From template…", without saving); actions — `actions/templates.ts` (list, save with replace confirmation, delete with confirmation) and `ProjectActions.newFromTemplate` (folder choice, as for a new project). There are no built-in templates yet.
* **Presets** (`Presets`, `PresetFolder`, `presets.rs`): `<state>/presets/<kind>/<name>.json` = `{ kind, params, state? }` (in the kind's folder name, the colon and other characters are replaced with `_`; the kind inside the file is checked on apply). The target is an `EditorTarget` (a track instrument or an effect node); a preset belongs to a kind and can be applied to any target of that kind. `apply` is one undo group "Preset 'name'": first the plugin state (`PluginStates::set`), then the parameters on top (`TrackControl::set_instrument_param` / `GraphControl::set_effect_param`); parameters the kind no longer has are skipped. RPC: `presets.list { kind }`, `presets.save { target, name }`, `presets.apply { target, name }`, `presets.remove { kind, name }` (`daw-rpc/src/presets.rs`). Interface: the `ui/common/PresetBar.tsx` bar (a list — choosing applies the preset, "Save…" with a name field, "✕" deletes the selected one) in the instrument window (`InstrumentWindow`) and in the `EffectPanel` effect panel (the graph inspector and the mixer insert popup); actions — `actions/presets.ts`. Mocks — `mock/handlers/templates.ts`, `mock/handlers/presets.ts` (in memory; no plugin states).
* **Tests:** `structure_of` and the preset file format — unit tests in `templates.rs`/`presets.rs`; contracts on a full session — `daw-bootstrap/tests/presets_templates.rs` (instrument and effect presets: save, apply in one undo step, delete, rejected targets and names; templates: structure without clips, sampler sound copied into the new project, the new project opened, overwrite and delete); wire — `daw-rpc/tests/arrangement.rs`.
* **Similar** (e.g. built-in templates): a second, read-only folder in `TemplateFolder::list`/`existing`.
