# Project templates and presets

Both jobs live in the application state folder (not in the project) and are implemented in `daw-persistence`; the contracts and the shared name rule (`check_preset_name`: the name becomes a file name) are in `daw-contracts/src/presets.rs`; on the frontend the same rules are in `presets/presetRules.ts`.

* **Templates** (`ProjectTemplates`, `TemplateFolder`, `templates.rs`): a template is a small project folder `<state>/templates/<name>/template.dawproj` + `samples/`, written by the same `ProjectStorage` as a project (copying sounds and relative paths work on their own). It keeps the structure (tracks with instruments and plugin state, colors, folders, the graph, the tempo map) and drops clips, automation, loop, markers and samples, except sampler sounds (parameters of kind `ParamKind::Sample` per the catalog, `structure_of`); the freeze mark is cleared. `create_project` writes the template into a new folder under the file's name (sounds are copied) and opens it with `ProjectIo::load`. RPC (`daw-rpc/src/templates.rs`): `templates.list`, `templates.save`, `templates.remove`, `project.createFromTemplate`. Interface: the `project/TemplatesDialog.tsx` window — from the project menu ("New from template…", "Save as template…") and from the welcome screen; actions — `project/templates.ts` and `ProjectActions.newFromTemplate` (folder choice, as for a new project). There are no built-in templates yet.
* **Presets** (`Presets`, `PresetFolder`, `presets.rs`): a file `<state>/presets/<kind>/<name>.json` (the kind's folder name is made safe; the kind inside the file is checked on apply). The target is an `EditorTarget` (a track instrument or an effect node); a preset belongs to a kind and can be applied to any target of that kind. `apply` is one undo group through the project contracts: first the plugin state (`PluginStates::set`), then the parameters on top (`TrackControl` / `GraphControl`); parameters the kind no longer has are skipped. RPC (`daw-rpc/src/presets.rs`): `presets.list`, `presets.save`, `presets.apply`, `presets.remove`. Interface: the `common/PresetBar.tsx` bar in the instrument window (`InstrumentWindow`) and in the `EffectPanel` effect panel (the graph inspector and the mixer insert popup); actions — `presets/presets.ts`.
* **Mocks** — `mock/handlers/templates.ts`, `mock/handlers/presets.ts` (in memory; no plugin states).
* **Tests:** `structure_of` and the preset file format — unit tests in `templates.rs`/`presets.rs`; the contracts on a full session — `daw-bootstrap/tests/all/presets_templates.rs`; wire — `daw-rpc/tests/all/arrangement.rs`.
* **Similar** (e.g. built-in templates): a second, read-only folder in `TemplateFolder::list`/`existing`.
