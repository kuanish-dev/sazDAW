# Cue (start position) and the timeline ruler strip

- **Contract** (`TransportControl`, `daw-contracts/src/transport.rs`): `set_cue` / `cue`; how `play`/`stop` use it is written on the trait. Implementation — one more atomic in `daw-transport` (`NO_CUE` = none); only the control side reads it, the audio thread is untouched; tests in `daw-transport/src/lib.rs`. Loading or creating a project clears the cue (`daw-project/src/service/mod.rs`). An audio take started from a stopped transport begins at the cue (`daw-audio-recorder`).
- **RPC/MCP:** `transport.setCue` (`daw-rpc/src/transport.rs`); the current cue is `cue` in the `tick` telemetry (`telemetry.rs`; `Tick.cue` in `api/types/transport.ts`). Mock — `mock/handlers/transport.ts` + `MockWorld.cue` (cleared by `install`).
- **UI.** `TransportActions.cueAt` (set the cue, then seek) and `clearCue`. The ruler strip is its own canvas: `ui/tracks/rulerRender.ts` draws bars, the loop, signature and marker flags and the cue flag (geometry `cueLayout.ts`); the rows canvas (`timelineRender.ts`) draws the marker lines, the loop shade and the dashed cue line; row coordinates start at 0 below the strip. Mouse on the strip goes through `tempoPointer` → `markerPointer` → `rulerPointer` (cue and loop gestures). Layout (`TracksView.tsx`): the toolbar and the strip are `sticky`; because CSS sticky does not work inside a horizontal scroller, the strip lives outside the rows' scroller and copies its `scrollLeft`, and `Timeline` renders the ruler into it through a `Portal`. Both canvases draw only the visible window (`createScrollWindow`).
- **Something similar above the rows** (e.g. a chord lane): grow `RULER_HEIGHT`, draw in `rulerRender.ts`, add a `*Pointer.ts` to the strip's chain in `Timeline.tsx`.
