# Automation: editing and live writing

* **Lanes and clips.** `AutomationLane` holds `AutomationClip`s that work like looped note clips: the points are a pattern in pattern ticks (from the clip start) repeated every `loop_ticks` over the clip length. Clips of a lane are kept sorted and never overlap; between clips the lane does not touch the param (its project value plays). Value at a tick — `daw_contracts::clip_value_at` / `lane_value_at` (`daw-contracts/src/automation.rs`, which also documents the loop seam).
* **Contract** `AutomationControl` (same file; one interface — "edit automation lanes and their clips"; its docs list the methods, the `MAX_*` limits and the errors, codes in `codes/automation.rs`). Every mutating call is one undo step; consecutive `set_points` on one clip coalesce. A new clip starts as a flat line at the param's current value (`ops::target_value`), so placing it changes nothing audible. Implementation `daw-project/src/automation.rs`; RPC `automation.addLane/removeLane/addClip/editClip/duplicateClip/removeClip/setPoints/drawShape`. Engine: `AutomationPlayer` (`daw-engine/src/automation.rs`) calls the allocation-free `lane_value_at`. Mix check `automationOutOfRange` (`daw-mixcheck/src/rules.rs`) reports out-of-range pattern points at their song tick in the first repeat.
* **Curves.** `AutoPoint::curve` shapes the segment to the next point. One formula, documented on the contract: `daw_contracts::curve_shape` / `value_at`. The engine plays with it, the interface draws with its mirror `app/src/domain/automationCurve.ts` (`curveShape`, `valueAt`, `curveThrough` — the inverse used when bending). A change of the formula is a change in both places.
* **Shapes.** `AutomationControl::draw_shape` replaces the pattern points in a range with a sine, triangle, saw, square or ramp (`AutomationShape`); one undo step. Point generation is pure — `daw-project/src/automation_shapes.rs`, mirrored for the mock by `shapePoints` in `domain/automationCurve.ts`.
* **One call for the AI.** `AutomationControl::add_drawn_clip` (RPC `automation.addDrawnClip { target, startTick, lengthTicks, drawing }`) finds or creates the target's lane, adds a clip and draws a shape or points over its whole pattern (`ClipDrawing`) in one edit, so a refused step leaves no empty lane behind; it returns `DrawnClip { lane, clip }`. It exists because building a mix over MCP cost three calls per automation (lane, clip, shape). The interface draws with the separate methods and does not use it, so it has no frontend wrapper or mock handler.
* **Timeline (frontend).** An automation lane is a timeline row: `domain/trackRows.ts` (`trackRows(…, ownedLanes(project))`) puts each lane right under the track that owns it (`domain/automation.ts: laneTrack` — the instrument's track, the track whose strip holds the node, for a connection the owner of `from`); lanes of buses and master go to a "Buses & master" block at the end; folder collapse and track order apply to them too. Mouse — `ui/tracks/lanePointer.ts`, drawing — `laneRender.ts` inside the shared `clipFrame.ts`, left column — `LaneHeader.tsx`. The selected lane/clip is `session.selection.automation()` (exclusive with the clip selection; set by actions via `ctx.selectAutomation`; keys in `state/clipKeys.ts`); the bottom `ClipPanel` then opens `ui/automation/AutomationClipPanel.tsx` (lengths, tools, shapes over the whole pattern) with `PatternEditor.tsx` editing one repeat. The write-mode selector is in `TimelineToolbar.tsx`. `editClip` and `setPoints` patch the project copy at once (`patchProject`), so a dropped clip or moved point is not drawn at its old place for a frame.
  * To add a clip operation: `api/api.ts` → `actions/automation.ts` → mock handler → a gesture in `lanePointer.ts` or a control in `AutomationClipPanel.tsx`. A new parameter kind needs `targetLabel`/`targetRange`/`paramValue`/`laneTrack` cases in `domain/automation.ts`.
* **Pattern editor (frontend).** Gestures — `ui/automation/patternPointer.ts` (its header lists them); the pencil stroke (`domain/controllers.ts: startStroke/extendStroke/strokeOver`) is shared with the piano roll controller lane. Keys — the `PATTERN_KEYS` table in `PatternEditor.tsx`, which also feeds the shortcut help; the lane takes keys while focused (`data-owns-keys`). The clipboard is `actions/automation.ts: copyPoints/pastedPoints`, one for every pattern while the app is open. Pure edits — `domain/automationEdit.ts`.
* **Live writing.** Contract `AutomationWriter` (`daw-contracts/src/automation_write.rs`): a global `AutomationWriteMode` (Off/Touch/Latch) that is run state, not in the project (RPC `automation.writeMode` / `automation.setWriteMode`, shown in the `tick` as `automationWrite`); `touch` is called right *before* the param is set through its owner, so the move joins the pass's undo step. Who reports:
  * the frontend action layer — `actions/paramTouch.ts: createParamTouch`, used by `actions/graph.ts` (volume, pan, effect params, connection levels), `actions/tracks.ts` (instrument params) and `actions/stage.ts`; only while playing with the mode on; a mouse/key up anywhere releases (`state/touchRelease.ts`); RPC `automation.touch` / `automation.release` / `automation.releaseAll`;
  * MIDI knobs — `ProjectMidiMappings` with `TouchEnd::Idle` (no release signal; ends after `TOUCH_IDLE_MS`).
  * Plugin windows do not report yet.
* **Writer** (`daw-automation-writer`; where points go and how a stretch joins the old pattern — its `lib.rs` and `stretch.rs` headers). It reads the play position from `TransportControl` and bar starts from `TempoControl`, writes through `AutomationControl` from a poll thread (`POLL_INTERVAL`, sends at most every `FLUSH_INTERVAL`). A touch opens the pass's edit group (`HistoryControl::begin_group`); stop/pause or mode `Off` clears the holds and closes the group = one undo step. While a target is written the engine does not play its lane: `AutomationHold::hold` → `EngineLink` (`daw-engine/src/link/held.rs`, atomic slots, no locks) → `AutomationPlayer` skips it, and the param's project value (moved by the performer) sounds. A lane or clip deleted while writing just stops its writing; other failures go to the log (`automation`, once per pass).
* **Mock.** `mock/handlers/automation.ts` mirrors the methods; live writing is simplified (a point per touch into the clip under the play position or a new clip from the bar start that grows during the pass; one undo step per pass).
* **Adding a parameter kind** to live writing: its `ParamTarget` must already be automatable; report its moves with `touch` from the action that sets it (and from MIDI if it can be mapped).
