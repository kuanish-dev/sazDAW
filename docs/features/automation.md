# Automation: editing and live writing

* **Lanes and clips.** `AutomationLane { id, target, clips }` — one lane per param; its `AutomationClip { id, start_tick, length_ticks, loop_ticks, points }` work like looped note clips: the points are a pattern in pattern ticks (`0..=loop_ticks`, from the clip start) repeated every `loop_ticks` over the clip length. Clips of a lane are kept sorted and never overlap; between clips the lane does not touch the param (its project value plays). Value at a tick — `daw_contracts::clip_value_at` / `lane_value_at` (`automation.rs`): local tick = `(tick - start) mod loop`; at the loop seam the last points hold (or lead to a point placed exactly at `loop_ticks`) up to the end of the repeat, and the next repeat restarts at its first point. Contract `AutomationControl` (one interface — "edit automation lanes and their clips"): `add_lane`/`remove_lane`, `add_clip(lane, start, length)` (loop = length capped at `MAX_CLIP_LOOP_TICKS`, starts as a flat line at the param's current value — `ops::target_value`), `edit_clip(AutomationClipEdit { start?, length?, loop? })` (a shorter loop drops points after it), `duplicate_clip` (at the clip end), `remove_clip`, `set_points`, `draw_shape` — every call one undo step (`set_points` of one clip coalesces). Implementation `daw-project/src/automation.rs`. Limits `MAX_LANES` 256, `MAX_AUTOMATION_CLIPS` 1024 per lane, `MAX_POINTS` 4096 per clip. Codes: `AT-011` clip not found, `AT-115` overlap, `AT-116` zero length/loop, `AT-117` end past `u32::MAX`, `AT-118` loop too long, `AT-119` point/shape after the loop end, `AT-212` too many clips. RPC `automation.addClip/editClip/duplicateClip/removeClip/setPoints/drawShape` (all take `lane` and `clip`). Engine: `AutomationPlayer` calls `lane_value_at` (binary search over the sorted clips, no allocation). Mix check `automationOutOfRange` reports out-of-range pattern points at their song tick in the first repeat.
* **Curves.** `AutoPoint { tick, value, curve }` — `curve` (`-1..=1`, JSON default 0) shapes the segment from this point to the next. One formula, documented on the contract: `daw_contracts::curve_shape` / `value_at` (`automation.rs`; `t^e` for `curve > 0`, `1 - (1-t)^e` for `curve < 0`, `e = 4^|curve|`). The engine plays with it (`daw-engine/src/automation.rs`), the interface draws with its mirror `app/src/domain/automationCurve.ts` (`curveShape`, `valueAt`, `curveThrough` — the inverse used when bending). A change of the formula is a change in both places.
* **Shapes.** `AutomationControl::draw_shape(lane, clip, ShapeRequest { from_tick, to_tick, shape, period_ticks, min, max })` replaces the pattern points in `from..=to` (pattern ticks, `to <= loop_ticks`; one undo step); shapes: sine (16 straight steps per period), triangle, saw, square (a jump is two points a tick apart), ramp up/down (period ignored). Point generation is pure: `daw-project/src/automation_shapes.rs`, mirrored by `shapePoints` for the mock. RPC `automation.drawShape { lane, clip, fromTick, toTick, shape, periodTicks, min, max }`. Codes `AT-112` (empty range), `AT-113` (period < `MIN_SHAPE_PERIOD`), `AT-114` (non-number curve).
* **Automation clips (frontend).** An automation lane is a timeline row: `domain/trackRows.ts` `trackRows(tracks, folders, ownedLanes(project))` puts each lane right under the track that owns it (`domain/automation.ts` `laneTrack`: instrument param → its track; a node's volume/pan/effect → the track whose strip — source or inserts — holds the node; a connection level → the owner of its `from`) and lanes of buses/master in a "Buses & master" block at the end; folder collapse and track order apply to them too. Values follow the backend formula in `domain/automationCurve.ts` (`clipValueAt`/`laneValueAt`). On the timeline `ui/tracks/lanePointer.ts` (select, move, resize, double-click adds a one-bar clip, right-click deletes) and `laneRender.ts` (curve and repeat lines inside the shared clip frame, `clipFrame.ts`) handle lane rows, `LaneHeader.tsx` is the left column. The selected lane/clip is `session.selection.automation()` (`{lane, clip|null}`, exclusive with the clip selection; actions set it via `ctx.selectAutomation`; ⌘D/Delete/Esc in `state/clipKeys.ts`), and the bottom `ClipPanel` opens `ui/automation/AutomationClipPanel.tsx` (clip and pattern length in bars, tools, shapes over the whole pattern) with `PatternEditor.tsx` editing one repeat. The write-mode selector is in `TimelineToolbar.tsx`. `editClip` and `setPoints` show the change in the project at once (`patchProject`), so a dropped clip or a moved point is not drawn at its old place for a frame before the refreshed project arrives. To add a clip operation: `api/api.ts` → `actions/automation.ts` → mock handler → gesture in `lanePointer.ts` or a control in `AutomationClipPanel.tsx`; a new parameter kind needs `targetLabel`/`targetRange`/`paramValue`/`laneTrack` cases in `domain/automation.ts`.
* **Pattern editor (frontend).** `ui/automation/patternPointer.ts`: select tool — click adds, drag moves the selection (snapped by the grabbed point), drag on empty space selects a box, Shift-click toggles, the middle handle or Alt-drag bends a segment (value tooltip while dragging); pencil tool — points on grid steps, replacing the stroke span (`domain/controllers.ts: startStroke/extendStroke/strokeOver`, shared with the piano roll controller lane). `PatternEditor.tsx` (keys by the table `PATTERN_KEYS`, which also feeds the shortcut help): Delete, ⌘C/⌘V (paste at the playhead; the clipboard is `actions/automation.ts: copyPoints/pastedPoints`, one for every pattern while the app is open), ⌘A, Esc on the focused lane (`data-owns-keys`), double-click types a value. Pure edits: `domain/automationEdit.ts`. The shape toolbar is in `AutomationClipPanel.tsx` (the whole pattern, the parameter's whole range).
* **Live writing.** Contract `AutomationWriter` (`daw-contracts/src/automation_write.rs`): global `AutomationWriteMode { Off, Touch, Latch }` (run state, not in the project; RPC `automation.writeMode` / `automation.setWriteMode`, shown in the `tick` as `automationWrite`), `touch(target, value, TouchEnd)` — called right *before* the param is set through its owner, `release(target)`, `release_all()`. Who reports: the frontend action layer (`actions/paramTouch.ts: createParamTouch`, used by `actions/graph.ts` — volume, pan, effect params, connection levels — and `actions/tracks.ts` — instrument params; only while playing with the mode on; a mouse/key up anywhere releases, `state/touchRelease.ts`) through RPC `automation.touch` / `automation.releaseAll`, and MIDI knobs (`ProjectMidiMappings`, `TouchEnd::Idle`: released after `TOUCH_IDLE_MS` without moves). Plugin windows do not report yet.
* **Writer** (`daw-automation-writer`). The play position comes from `TransportControl` (its own reference, not the core's). A touch opens the pass's edit group (`HistoryControl::begin_group`; the param moves themselves join it) and starts a stretch for the target (lane created with `add_lane` if missing) in one clip: the clip under the play position, written at its pattern position (in a looped clip the pattern of every repeat changes), or — outside clips — a new clip from the bar start of the touch (`TempoControl::tempo_map().bar_start`, not before the previous clip's end) that grows (length = loop, whole beats) with the writing up to the next clip or `MAX_CLIP_LOOP_TICKS`. The poll (20 ms) extends active stretches to the play position (Latch, or a held Touch), ends idle knobs, starts a new stretch when the position leaves the clip, crosses the loop seam or jumps back (in whatever clip is there then), and sends clips with `edit_clip` (growth) + `set_points` at most every 100 ms. A stretch replaces the old pattern points inside its span and adds joins a tick before and (except in a growing clip) after it with the old values (`stretch.rs`); close moves (< 30 ticks) merge into one point. While a target is written the engine does not play its lane: `AutomationHold::hold(lanes)` → `EngineLink` (`link/held.rs`, atomic slots, no locks) → `AutomationPlayer` skips it and the param's project value (moved by the performer) sounds. Stop/pause or mode `Off` ends the pass: holds are cleared, the group closes = one undo step. A lane or clip deleted while writing just stops its writing; other failures go to the log (`automation`, once per pass).
* **Mock.** `mock/handlers/automation.ts` mirrors the methods; live writing is simplified (a point per touch into the clip under the play position or a new clip from the bar start that grows during the pass; one undo step per pass).
* **Adding a parameter kind** to live writing: its `ParamTarget` must already be automatable; report its moves with `touch` from the action that sets it (and from MIDI if it can be mapped).
