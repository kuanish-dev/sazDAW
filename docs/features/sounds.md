# Sounds: the project folder, the sound browser and dragging a sound

**Sounds: one source — the project folder.** A sample = a file in `<project>/samples`. The sound browser (the "Tracks" page, below the timeline; parts: `PlaceTabs` — sections, `SoundRow` — a row and its actions; which files are already samples is remembered by `SoundBrowser` itself) shows two sections: "Project" (the source, and also the drop target) and "Packs" (external linked folders for preview only; ✕ removes the link, the files are not touched). Previewing (click, ↑/↓, Esc, Space while the list has focus — the list is marked `data-owns-space` so the global Space "play/pause" does not fire) copies nothing. As soon as a sound from a pack is put to work ("To project", "＋", "To timeline", "To editor", dragging onto the timeline or onto "Project"), `api.samples.import` copies it into the project folder (idempotently), and the project no longer depends on the pack. Actions: `actions/samples.ts` (`importSample`, `importFiles`, `removeSample`), `actions/soundPlacement.ts` (`addSoundToTrack`, `addSoundToTimeline`, `editSound`, `dropSample`, `dropAsNewTrack`), `actions/soundBrowser.ts` (folders and packs), `actions/preview.ts` (previewing). The "Samples" tab is only the editor of the selected sound. The browser sees sounds only inside the project folder and the linked folders: the shared "places" logic (root, "Project", links, "never go above the root") is in `ui/sounds/soundPlaces.ts`; the computer as a whole is not shown, external files are brought in through the explicit "Import files…" dialog. The drop target is `ui/tracks/timelineDrop.ts` (dragover → a clip "ghost" snapped to the grid, drop → `soundPlacement.dropSample(source, track, tick)`). A drop onto an existing track is decided by the pure `planDrop` (`domain/dropSample.ts`): on an instrument track the sound becomes its instrument and name (`tracks.setInstrument(id, "sampler", {sample, root}, name)`, the notes stay, one undo step; the "ghost" highlights the whole row); on an audio track it becomes a clip if there is room; if the spot is taken, the drop is not allowed. New tracks are not created by guessing from the sound's length but by an explicit choice: while a sound is being dragged, two labeled zones appear below the last track (`ui/tracks/DropZones.tsx`): "＋ Instrument" (`soundPlacement.dropAsNewTrack(source, "instrument")`: a sampler track named after the sound with a one-bar clip containing a single note, so the sound plays right away) and "+ Ready block" (`"block"`: an audio track with the whole sound as a clip). The clip snaps to the bar of the playback position; a clip with a note is a single `clips.addNote` call with `notes`, but creating the track and the clip is not yet one undo step (two API calls). The "ghost" uses the same `planDrop`, so the picture and the result match. Reordering tracks: the "⠿" handle in `TrackHeader` + `ui/tracks/trackReorder.ts` (pointer events, gap between rows → `tracks.move`), pure `insertSlot`/`moveIndex` in `domain/tracks.ts`; the order of timeline rows comes from `project.tracks`.

Dragging a sound onto the timeline: `ui/common/dragSample.ts` uses pointer events, not HTML5 drag & drop (in a Tauri window on macOS, WebKit, it does not start on `user-select: none` and depends on the window itself intercepting drags). The source (`SoundRow`, `startSampleDrag`) starts dragging after the mouse moves 5 px, the label at the cursor is `SampleDragLabel`; drop targets register via `registerSampleDrop(element, {over, leave, drop})` (timeline — `timelineDrop.ts`, "Project" and the list — `SoundBrowser`/`PlaceTabs`), and the target under the cursor is found with `elementFromPoint`; Esc and releasing outside a target cancel; the click after a drag is suppressed. The Tauri window is created with `"dragDropEnabled": false` (`app/src-tauri/tauri.conf.json`): with file-drop interception enabled, the wry handler on macOS always takes the event for itself, and an HTML5 `drop` inside the page never happens at all (the sound "won't drop"). The app does not accept files dragged from Finder into the window — they are brought in through the "Import…" dialog.
