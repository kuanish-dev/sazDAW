# Sounds: the project folder, the sound browser and dragging a sound

**One source — the project folder.** A sample = a file in `<project>/samples`. The sound browser (the "Tracks" page, below the timeline: `ui/sounds/SoundBrowser.tsx`, sections `PlaceTabs`, rows `SoundRow`) shows "Project" (the source and the drop target) and "Packs" (external linked folders for preview only; removing a link does not touch the files). Previewing copies nothing; the list is marked `data-owns-space`, so Space replays the sound instead of play/pause. As soon as a sound from a pack is put to work (any "to project/track/timeline/editor" action or a drag), `api.samples.import` copies it into the project folder (idempotently), and the project no longer depends on the pack. The browser sees only the project folder and the linked folders (the shared "places" logic, "never go above the root", is `ui/sounds/soundPlaces.ts`); the computer as a whole is not shown, external files come in through the explicit "Import files…" dialog. The "Samples" tab is only the editor of the selected sound.

* **Actions:** `actions/samples.ts` (import, remove), `actions/soundPlacement.ts` (putting a sound on a track, the timeline, the editor; the drops), `actions/soundBrowser.ts` (folders and packs), `actions/preview.ts` (previewing).
* **Dropping onto a track:** the drop target is `ui/tracks/timelineDrop.ts` (a clip "ghost" snapped to the grid → `soundPlacement.dropSample`). The decision is the pure `planDrop` (`domain/dropSample.ts`), used by both the ghost and the drop, so the picture and the result match: on an instrument track the sound becomes its sampler instrument and name (notes stay, one undo step); on an audio track it becomes a clip if there is room; if the spot is taken, the drop is not allowed.
* **New tracks** are not created by guessing from the sound's length but by an explicit choice: while a sound is dragged, two zones appear below the last track (`ui/tracks/DropZones.tsx` → `soundPlacement.dropAsNewTrack`): "Instrument" (a sampler track with a one-bar clip with one note, so the sound plays right away) and "Ready block" (an audio track with the whole sound as a clip), at the bar of the playback position. Limitation: creating the track and the clip is not yet one undo step (two API calls).
* **Reordering tracks:** the "⠿" handle in `TrackHeader` + `ui/tracks/trackReorder.ts` (→ `tracks.move`), pure `insertSlot`/`moveIndex` in `domain/tracks.ts`; the row order comes from `project.tracks`.

**Dragging a sound** (`ui/common/dragSample.ts`) uses pointer events, not HTML5 drag & drop: in a Tauri window on macOS (WebKit) HTML5 dragging does not start on `user-select: none` and depends on the window itself intercepting drags. The source calls `startSampleDrag`, drop targets register with `registerSampleDrop` (the timeline — `timelineDrop.ts`, "Project" and the list — `SoundBrowser`/`PlaceTabs`), the label at the cursor is `SampleDragLabel`. The Tauri window is created with `"dragDropEnabled": false` (`app/src-tauri/tauri.conf.json`): with file-drop interception enabled, the wry handler on macOS always takes the event for itself, and an HTML5 `drop` inside the page never happens (the sound "won't drop"). So the app does not accept files dragged from Finder into the window — they come in through the "Import…" dialog.
