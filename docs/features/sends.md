# Sends: pre/post-fader and connection level automation

A send is an ordinary graph connection with a level (`Edge` in `daw-contracts/src/graph.rs`); there is no separate "send" entity.

* **Contract.** `Edge::pre_fader` (default post-fader). A **pre-fader** send takes the node's audio before its volume and pan: moving the fader or pan, and their automation, do not affect the send. **The node's mute and another node's solo silence it too** — a muted track is silent entirely (simpler and more predictable; "quiet fader but loud reverb" is done by pulling the fader to zero). Only a connection from a node with a fader — a source or a bus (`Graph::check_pre_fader`; otherwise `graph::PRE_FADER_NEEDS_STRIP`) — can be pre-fader. Toggled by `GraphControl::set_edge_pre_fader` (RPC `graph.setEdgePreFader { from, to, preFader }`, one undo step). Pre-fader sends (like sidechain) are branches, not the track's path: `insert_effect` and `set_output` do not touch them, `Graph::chain` does not see them; `remove_effect_keep_path` gives the new connection the input send's kind.
* **Level automation.** Target `ParamTarget::EdgeLevel { from, to, sidechain }` (sidechain connections are automated separately), range `0..=MAX_LEVEL`. A lane lives as long as its connection: the rule is held by a single function `daw-project/src/ops.rs: drop_stale_edge_lanes` (called after every edit that removes edges), and `move_edge_lane` moves the lane along with the connection when an effect is inserted. A lane for a nonexistent connection is `graph::NO_SUCH_EDGE`.
* **Engine** (`daw-engine/src/mixer/mod.rs`). For a source or bus with pre-fader sends, the audio is copied before the fader into a single preallocated `pre_fader` buffer (nodes are processed one at a time, so one is enough); `tap_pre_fader` fades it out smoothly on mute/solo. Pre-fader connections read it instead of the node's output; PDC aligns them like any connection. Automation overrides the connection level for the segment (`override_edge_level`, reset in `clear_overrides`), and a level change is ramped across the segment (`EdgeRt::ramp`, `mix_ramped`; the same in the delay line) to avoid steps. Nothing is allocated or locked.
* **Frontend.** The "pre-fader / post" toggle is in `ui/graph/EdgePath.tsx: EdgeControls` (only on an ordinary connection from a track or bus, `domain/graph.ts: canPreFader`), action `actions/graph.ts: setEdgePreFader`; the inspector marks such connections "pre". Lanes "Send: A → B" (and "Sidechain: A → B") are added from the level control's right-click menu like any parameter (`ui/common/ParamMenu.tsx`); labels and ranges — `domain/automation.ts: targetLabel/targetRange`. The mock repeats the rules (`mock/handlers/graph.ts`, `mock/graphOps.ts: dropStaleEdgeLanes/moveEdgeLane`, target check in `mock/handlers/automation.ts`).
* **Tests:** contract — `daw-project/src/tests/sends.rs` and `daw-contracts/src/graph/tests.rs`; engine — `daw-engine/src/tests/sends.rs`; RPC wire — `daw-rpc/tests/all/graph.rs`.
