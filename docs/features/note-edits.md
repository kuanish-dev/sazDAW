# Musical note edits and the controller lane in the piano roll

* **Contract.** `NoteControl::transform_notes(clip, ids: Option<Vec<NoteId>>, NoteTransform)` (`daw-contracts/src/notes.rs`): one edit is one undo step; no `ids` — all notes of the clip, an empty list — `Invalid`, an unknown note — `NotFound`, a clip without notes — an empty response without a step. `NoteTransform`: `Quantize { grid, strength 0..1, ends }` (grid from the start of the content, nearest line, halfway — forward; `ends` — the end too, no closer than one step to the start), `Humanize { timing_ticks ≤ MAX_HUMANIZE_TICKS, velocity ≤ 126, seed }` (mulberry32 generator: one seed — one result; no seed — taken from the clock), `Transpose { semitones }` (a note beyond 0..127 — `Invalid`, nothing changes: we do not clamp, so a chord is not silently flattened), `FitToScale { root 0..11, scale: Scale }` (nearest degree, halfway — down), `Legato` (up to the start of the next note in the group of any pitch; a chord — up to one common start; the last notes do not change). Groove and variations are below. Timing edits do not push notes past the content (with a manual length the note is moved back). Why a method in `NoteControl` rather than its own trait: the job is the same — "edit the notes of a clip"; only the rule changes; the rules themselves are pure functions in `daw-project/src/note_transforms.rs`, separate from the content rules in `note_rules.rs`.
* **RPC** (`daw-rpc/src/notes.rs`): `notes.quantize { clip, ids?, grid, strength? = 1, ends? = false }`, `notes.humanize { clip, ids?, timingTicks, velocity, seed? }`, `notes.transpose { clip, ids?, semitones }`, `notes.fitToScale { clip, ids?, root, scale: "major"|"minor"|"dorian"|"phrygian"|"lydian"|"mixolydian"|"harmonicMinor"|"pentatonicMajor"|"pentatonicMinor"|"chromatic" }`, `notes.legato { clip, ids? }` → the group's notes after the edit. The interface and the AI use the same logic.
* **Frontend.** The mock repeats the rules one to one — `domain/noteTransforms.ts` (rounding and mulberry32 as in Rust; matching numbers are pinned by the test `humanize_numbers_match_the_frontend_mock`); the list of scales `SCALES` and `inScale` for row highlighting live there too. Actions — `actions/notes.ts` (`quantize`, `humanize`, `transpose`, `fitToScale`, `legato`, `setControllerLane`). Panel — `ui/pianoroll/NoteTools.tsx`: "Quantize / Humanize / Transpose / To scale / Legato" over the selection (no selection — over all notes), parameters in small popovers; "To scale" keeps the piano roll's scale and turns on highlighting of its rows (`render.ts`, `GridView.scale`). ⌥Q quantizes to the current grid (plain Q is taken by the keyboard piano).
* **Controller lane** (`ControllerLaneView.tsx`, collapsible so it does not take space from the note grid): lane choice (Pitch bend, Modulation CC1, Sustain CC64, Expression CC11, Aftertouch, "Other CC…"; lanes with points are marked "●"), dragging draws points on grid steps and replaces the points in the covered span, right-click deletes the nearest point; one gesture is one `notes.setControllerLane` edit (empty — the lane is removed), which shows the lane at once (`patchProject`), like `notes.updateNotes` does for a note drag, so a finished gesture never flashes the old shape. Pure rules — `domain/controllers.ts` (kinds and labels, value limits, `drawStroke`, `removeNear`, `strokeSegment`, and the pencil stroke `startStroke`/`extendStroke`/`strokeOver` shared with automation patterns), step drawing — `controllerRender.ts`, mock checks — `mock/noteOps.ts: setControllerLane` (like `note_rules::set_controller_lane`).
* **Groove** (`NoteTransform::Groove { template, amount }` and `GrooveFromClip { source, amount }`; rules — `daw-project/src/groove.rs`). A groove is a table on a sixteenth-note grid: for each step, a start offset in ticks and a velocity in percent. A note takes the step of the nearest sixteenth from the start of the content (`i % table length`); the offset and the velocity deviation from 100 % are applied scaled by `amount` 0..1; the length is kept, the note does not leave the content. **This is a note edit, not a playback setting:** the offset is added to the current position (straight notes get exactly the template, applying the groove again adds it once more); to revert, undo. `GrooveTemplate` templates (a table per beat of four sixteenths, plain data): `swing { grid: eighth | sixteenth, percent 50..75 }` (the second eighth of the beat at `percent` % of the pair, sixteenths between them halfway; `sixteenth` — MPC swing), `laidBack { ticks ≤ 120 }` ("laid back": everything off the beat is later), `pushed` ("pushed": earlier), `accent { percent 100..200 }` (notes on beats are louder). "Take groove from clip": `ProjectNotes` extracts a table from the reference clip (`extract_groove`: the bar of the meter at its start; for each sixteenth, the average deviation from the line and the average velocity relative to the clip's average velocity; an empty step — no change) and passes it to the pure function through `Surroundings` (another clip is not the business of a function over one content). A deviation larger than half a sixteenth belongs to the neighboring line — strong eighth swing (> 62 %) cannot be extracted this way. RPC: `notes.groove { clip, ids?, template, amount? = 1 }`, `notes.grooveFromClip { clip, ids?, sourceClip, amount? = 1 }`. Tests — `daw-project/src/tests/groove.rs`.
* **Pattern variations** (`NoteTransform::Vary(Variation)`, rule — `daw-project/src/variation.rs`): the only edit that removes and adds notes (the response is the remaining notes of the group, then the new ones with new ids). `Variation { seed?, density −1..1, pitch, rhythm, velocity 0..1, scale?: { root, scale } }` — probabilities per note. Each note of the group, in order, takes exactly six random numbers (mulberry32) regardless of the settings — so moving one slider does not reshuffle the rest: remove (`-density`), neighboring pitch (a scale degree or, without a scale, a neighboring pitch among the group's pitches; at the edge — the other way), rhythm (a sixteenth earlier / later, split in half on the grid, merge with the next note of the same pitch), velocity spread (up to ±32). Notes on the first beat of a bar (bar of the meter at the clip start) are anchors: they do not move or change pitch, and are removed only when `density` < −0.5 (and with probability at most 0.5). Positive density adds `round(density · n)` notes on free sixteenths within the content length; pitch, velocity and length come from a random note of the group. Any change after which notes of the same pitch would overlap or a note would leave the content is skipped. `NoteControl::vary_to_new_clip` — a copy of the clip right after it (`clip_rules::copy_after`, the same as `duplicate_clip`) and a variation of the copy in one core edit: one undo step. RPC: `notes.vary { clip, ids?, seed?, density?, pitch?, rhythm?, velocity?, scale? }` (missing field — 0), `notes.varyToNewClip { … }` → the new clip. Without a seed both pick a random one. Tests — `daw-project/src/tests/variation.rs`, wire — `daw-rpc/tests/note_transforms.rs`.
* **Groove and variation frontend.** Copies of the rules — `domain/groove.ts` (which also holds the ready-made `GROOVE_PRESETS` for the menu) and `domain/variation.ts`; the generator and rounding are shared from `domain/noteTransforms.ts` (`random`, `roundAway`, `fit`). Matching numbers are pinned by the tests `groove_numbers_match_the_frontend_mock` and `variation_numbers_match_the_frontend_mock` (numbers computed by the TS copy). Mock: `notes.groove/grooveFromClip/vary/varyToNewClip` in `mock/handlers/notes.ts` (the clip copy uses the shared `mock/clipRules.ts: duplicateClip`). Actions — `groove`, `grooveFromClip`, `vary`, `varyToNewClip` in `actions/notes.ts`; the "Groove ▾" panels (template, amount, "From clip" — another note clip in the project) and "Variation ▾" (sliders, seed with 🎲, "In scale" — the scale from "To scale", "Apply" / "To new clip") — in `NoteTools.tsx`.
* **How to add another note edit:** a `NoteTransform` variant + a function in `note_transforms.rs` and a test, an RPC line, a copy in `domain/noteTransforms.ts` and a mock handler, an action method and a button in `NoteTools`.
