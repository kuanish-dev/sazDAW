# Musical note edits and the controller lane in the piano roll

* **Contract.** `NoteControl::transform_notes(clip, ids, NoteTransform)` (`daw-contracts/src/notes.rs`; the docs of `NoteTransform`, `GrooveTemplate` and `Variation` give each edit's rules and errors): one edit is one undo step; no `ids` means all notes of the clip. Variants: quantize, humanize, transpose, fit to scale, legato, groove, groove from clip, vary. Why a method in `NoteControl` rather than its own trait: the job is the same — "edit the notes of a clip"; only the rule changes. The rules are pure functions in `daw-project/src/note_transforms.rs` (plus `groove.rs` and `variation.rs`), separate from the content rules in `note_rules.rs`.
* **RPC** (`daw-rpc/src/notes.rs`): `notes.quantize`, `notes.humanize`, `notes.transpose`, `notes.fitToScale`, `notes.legato`, `notes.groove`, `notes.grooveFromClip`, `notes.vary`, `notes.varyToNewClip`; each returns the group's notes after the edit (`varyToNewClip` — the new clip). The interface and the AI use the same logic.
* **Frontend.** The mock repeats the rules one to one in `pianoroll/noteTransforms.ts` (rounding and the mulberry32 generator as in Rust; matching numbers are pinned by the test `humanize_numbers_match_the_frontend_mock`); `SCALES` and `inScale` for row highlighting live there too. Actions — `pianoroll/notes.ts`. Panel — `pianoroll/NoteTools.tsx`: the edits work over the selection, or over all notes without one; "To scale" keeps the piano roll's scale and turns on highlighting of its rows (`render.ts`, `GridView.scale`). ⌥Q quantizes to the current grid (`pianoroll/editing.ts`; plain Q is taken by the keyboard piano).
* **Controller lane** (`pianoroll/ControllerLaneView.tsx`; mouse — `controllerPointer.ts`, drawing — `controllerRender.ts`). One gesture is one `notes.setControllerLane` edit, and the action patches the project copy at once (`patchProject`), like the `updateNotes` action does for a note drag, so a finished gesture never flashes the old shape. Pure rules — `pianoroll/controllers.ts` (kinds and labels, value limits, the pencil stroke `startStroke`/`extendStroke`/`strokeOver` shared with automation patterns); mock checks — `mock/noteOps.ts: setControllerLane` (mirror of `note_rules::set_controller_lane`).
* **Groove** (`NoteTransform::Groove` and `GrooveFromClip`; rules — `daw-project/src/groove.rs`). A groove is a table on the sixteenth grid (a start offset and a velocity per step). **This is a note edit, not a playback setting:** the offset is added to the current position, so applying it again adds it once more; to revert, undo. "Take groove from clip": `ProjectNotes` extracts the table from the reference clip (`extract_groove`) and passes it to the pure function through `Surroundings` — another clip is not the business of a function over one content. Limitation: a deviation larger than half a sixteenth belongs to the neighbouring line, so strong eighth swing (> 62 %) cannot be extracted. Tests — `daw-project/src/tests/groove.rs`.
* **Pattern variations** (`NoteTransform::Vary(Variation)`, rule — `daw-project/src/variation.rs`): the only edit that removes and adds notes. Each note draws a fixed number of random numbers (`DRAWS_PER_NOTE`) regardless of the settings, so moving one slider does not reshuffle the rest. `NoteControl::vary_to_new_clip` makes a copy of the clip right after it (`clip_rules::copy_after`, the same as `duplicate_clip`) and varies the copy in one core edit — one undo step. Tests — `daw-project/src/tests/variation.rs`, wire — `daw-rpc/tests/all/note_transforms.rs`.
* **Groove and variation frontend.** Copies of the rules — `pianoroll/groove.ts` (also the ready-made `GROOVE_PRESETS` for the menu) and `pianoroll/variation.ts`, sharing the generator and rounding of `pianoroll/noteTransforms.ts`; matching numbers are pinned by `groove_numbers_match_the_frontend_mock` and `variation_numbers_match_the_frontend_mock`. Mock — `mock/handlers/notes.ts` (the clip copy uses `mock/clipRules.ts: duplicateClip`). The "Groove" and "Variation" panels are in `NoteTools.tsx`.
* **How to add another note edit:** a `NoteTransform` variant + a function in `note_transforms.rs` and a test, an RPC line, a copy in `pianoroll/noteTransforms.ts` and a mock handler, an action method and a button in `NoteTools`.
