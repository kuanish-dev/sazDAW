# `src/ui/` — the interface

`src/ui/*` by section: `shell` (the window frame: `ActivityBar` — view icons on the left, `StatusBar` — project, hover hint `HintText`, tempo, audio format, PDC, CPU, error-log shortcut; turns red while recording), `transport`, `tracks` (timeline, headers, automation), `pianoroll`, `drums`, `graph`, `mixer` (the "Mixer" page), `stage` (the "Stage" page), `samples`, `sounds`, `settings` (the "Settings" page), `common` (shared components and techniques: `canvas.ts`, `pointer.ts`, `theme.ts` `palette()`, `icons.tsx` (16px inline SVG line icons in `currentColor`; no icon fonts or packages), `InlineRename`, `MuteSolo`, `PanKnob`, `ChannelUtility`, `PickSelect`, `Knob`, `Fader`, `Modal`…). Only view state and calls to `session.actions.*`; shared session state is changed only by session intents

Knows about: state, actions, domain.

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [audio-export](../../../docs/features/audio-export.md), [automation](../../../docs/features/automation.md), [bounce](../../../docs/features/bounce.md), [channel-utility](../../../docs/features/channel-utility.md), [cue](../../../docs/features/cue.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-meter](../../../docs/features/master-meter.md), [master-visualizer](../../../docs/features/master-visualizer.md), [midi-controllers](../../../docs/features/midi-controllers.md), [note-edits](../../../docs/features/note-edits.md), [preferences](../../../docs/features/preferences.md), [processing-graph](../../../docs/features/processing-graph.md), [recording](../../../docs/features/recording.md), [sends](../../../docs/features/sends.md), [sidechain](../../../docs/features/sidechain.md), [song-loop](../../../docs/features/song-loop.md), [sounds](../../../docs/features/sounds.md), [templates-and-presets](../../../docs/features/templates-and-presets.md), [tempo-map](../../../docs/features/tempo-map.md), [virtual-stage](../../../docs/features/virtual-stage.md), [warping](../../../docs/features/warping.md).

**Look** (VS Code "Dark/Light Modern" style): all colors are CSS variables in `src/index.css` (`@theme` for dark, `:root[data-theme="light"]` for light, `data-accent` rules for the accent; the canvas palette is read by `ui/common/theme.ts`). Surfaces are flat — `bg` (editor area), `panel` (side bars, strips, status bar), 1px `line` borders, radius ≤ 4px (Tailwind radius and shadow tokens are overridden), 13px UI text. Shared classes: `.btn` (secondary) with `.btn-primary`, `.btn-ghost`, `.btn-icon` (square, for an icon) and `.btn-on` (pressed toggle); `.field` (inputs and selects), `.panel`, `.label`, `.section-header` (small uppercase strip), `.menu-item` (menus). Text on an accent background uses `text-on-accent`, list selection `bg-select`, ghost hover `bg-hover`. A new control uses these classes and tokens instead of raw colors.

**Motion and live visuals.** One short tempo for the whole app, all in `src/index.css` ("Motion"): duration and easing tokens (`--motion-fast/base/slow`, `--ease-out`, `--ease-spring`) and classes — `.anim-pop` (menus, popovers, dialogs; grows from the corner it is anchored to, an `origin-*` utility changes it), `.anim-fade` (backdrops, tooltips), `.anim-toast`, `.anim-view` (the view wrapper in `App.tsx`, re-created on every tab switch by a keyed `Show`), `.anim-rise` (welcome screen blocks, staggered by `animation-delay`), `.btn-on` and `.anim-toggle` (a toggle pops when it turns on), `.btn:active` (a press sinks), `.knob`/`.knob-active` (glow), `.playhead`/`.playhead-cap`, `.beat-dot-a/b` and `.beat-ring-a/b`. Keyframes move only `opacity`, `scale` and `translate`, and entrances fill `backwards`: they compose with inline transforms (the dragged instrument window), and nothing keeps a transform after it ends (a kept transform would make the element the containing block of its `fixed` menus). The system's "reduce motion" setting turns CSS motion off; loops driven from code check `ui/common/motion.ts: prefersReducedMotion()`. Live visuals: the timeline glow layer (`ui/tracks/activityRender.ts`: a second, transparent canvas over the rows, redrawn from `smoothPlayhead` on every frame but drawing only the clips under the playhead — lit notes with an afterglow of a sixteenth and a glowing outline of every clip being played; muted tracks stay dark), the track header's level glow (`TrackHeader.tsx`, a background gradient so it stays under the controls), meters with a peak-hold tick and a clip light (ballistics `domain/mixer.ts: stepMeter`, state `state/levels.ts`, picture `ui/common/Meter.tsx`; readings that already fall at their source, like the input level, go through `plainLevel`), the beat lights and the Play button pulse (`ui/transport/BeatLights.tsx: createBeat`, a memo over `smoothPlayhead` that changes only on a new beat; the lit element swaps between two copies of its keyframes by beat parity, so the animation restarts on every beat), the welcome screen's drifting waveforms (`ui/WelcomeBackdrop.tsx`), and the master visualizer ([docs/features/master-visualizer.md](../../../docs/features/master-visualizer.md)). A new animation reuses a class or token from "Motion"; a new per-frame drawing reads `smoothPlayhead` and keeps its per-frame work small, like the glow layer — never a heavy canvas.

Large components are split by role: the assembling component holds the view state, drawing goes to `*Render.ts`, mouse handling to `*Pointer.ts`/`pointer.ts`, geometry to `*Layout.ts`. Piano roll (`src/ui/pianoroll/`): `PianoRoll.tsx` (assembly), `render.ts`, `pointer.ts` (`createPianoRollPointer`: the grid), `velocityPointer.ts`, `editing.ts` (selection edits and keys), `pianoRollLayout.ts`, `PianoRollToolbar.tsx`, `NoteTools.tsx` (musical edits with parameter panels), `ControllerLaneView.tsx` + `controllerRender.ts` + `controllerPointer.ts` (controller lane), `StepGrid.tsx`. Graph (`src/ui/graph/`): `GraphView.tsx` (assembly), `GraphCanvas.tsx`, `pointer.ts` (`createGraphPointer`), `graphSelection.ts`, `graphLayout.ts`, `NodeCard`/`NodeStrip`/`Inspector`, `SignalPath` (the signal path view). Sample editor (`src/ui/samples/`): `SampleEditorView.tsx` (assembly), `sampleWave.ts` (waveform and view window), `SampleList`, `SampleToolbar`, `WaveformCanvas` + `waveformRender.ts` + `waveformPointer.ts`, `Overview`, `ExtractPanel`. Automation pattern editor (`ui/automation/`): `AutomationClipPanel` (lengths, tool, shapes), `PatternEditor` (assembly, keys, value entry), `patternPointer.ts` (gestures), `patternRender.ts`. Drum part (`src/ui/drums/`): `DrumPartDialog` (assembly), `PatternBrowser`, `PartList`, `DrumKitPicker`; its audition, like the chord part's, is `ui/common/loopPreview.ts`. The backend mock is organized the same way: `src/mock/world.ts` (state, catalog, history), `src/mock/handlers/*` (methods by area, including `drums.ts`), `meters.ts`, `liveSound.ts` (the sound of the master visualizer and the effect visuals), `MockRpc.ts` (assembly). A new shared technique (a canvas matched to screen density, the mouse point, a theme color) goes into `ui/common`, not copied into a section — as did the selection box (`canvas.ts: drawSelectionBox`), the visible-window test (`scrollWindow.ts: inWindow`), the bars stepper (`BarsStepper`), the looping audition (`loopPreview.ts`) and track colors (`trackColors.ts: trackColorOf`/`clipColorOf`, by the track's number in the project, so the header, the mixer strip and the clips agree). On the timeline every clip-shaped thing — note, audio and automation clips, crossfades, the drop ghost — takes its rectangle from `timelineLayout.ts: spanRect`, pixels → ticks from `tickAtX`, and its look from `ui/tracks/clipFrame.ts: drawClipFrame` (body, title strip, outline; the clip draws its own content inside).
