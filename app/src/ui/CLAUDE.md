# `src/ui/` — the interface

`src/ui/*` by section: `shell` (the window frame: `ActivityBar`, `StatusBar`, hover hint `HintText`), `transport` (the top strip, its project menu and the edit history panel `HistoryPanel.tsx`: see "The history as a list" in [daw-project](../../../crates/daw-project/CLAUDE.md)), `tracks` (timeline, headers, automation), `pianoroll`, `automation` (the automation pattern editor), `drums`, `chords`, `graph`, `effects`, `mixer`, `stage`, `samples`, `sounds`, `settings`, `common` (shared components and techniques: `canvas.ts`, `pointer.ts`, `theme.ts` `palette()`, `icons.tsx` (inline SVG in `currentColor`; no icon fonts or packages), `InlineRename`, `MuteSolo`, `PanKnob`, `ChannelUtility`, `PickSelect`, `Knob`, `Fader`, `Modal`…). Only view state and calls to `session.actions.*`; shared session state is changed only by session intents

Knows about: state, actions, domain.

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [audio-export](../../../docs/features/audio-export.md), [automation](../../../docs/features/automation.md), [bounce](../../../docs/features/bounce.md), [channel-utility](../../../docs/features/channel-utility.md), [cue](../../../docs/features/cue.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-meter](../../../docs/features/master-meter.md), [master-visualizer](../../../docs/features/master-visualizer.md), [midi-controllers](../../../docs/features/midi-controllers.md), [note-edits](../../../docs/features/note-edits.md), [preferences](../../../docs/features/preferences.md), [processing-graph](../../../docs/features/processing-graph.md), [recording](../../../docs/features/recording.md), [sends](../../../docs/features/sends.md), [sidechain](../../../docs/features/sidechain.md), [song-loop](../../../docs/features/song-loop.md), [sounds](../../../docs/features/sounds.md), [templates-and-presets](../../../docs/features/templates-and-presets.md), [tempo-map](../../../docs/features/tempo-map.md), [virtual-stage](../../../docs/features/virtual-stage.md), [warping](../../../docs/features/warping.md).

**Look** (VS Code "Dark/Light Modern" style, described at the top of `src/index.css`): all colors are CSS variables in `src/index.css` (`@theme` for dark, `:root[data-theme="light"]` for light, `data-accent` rules for the accent); canvases read them through `ui/common/theme.ts`. A new control uses the shared classes (`.btn` and its variants, `.field`, `.panel`, `.label`, `.section-header`, `.menu-item`) and color tokens (`text-on-accent`, `bg-select`, `bg-hover`…) instead of raw colors.

**Motion.** One short tempo for the whole app: the duration and easing tokens and the `.anim-*`/`.beat-*` classes are in `src/index.css` ("Motion"); a new animation reuses them. Keyframes move only `opacity`, `scale` and `translate`, and entrances fill `backwards` (why: the comment there). The system's "reduce motion" setting turns CSS motion off; loops driven from code check `ui/common/motion.ts: prefersReducedMotion()`.

**Live visuals**: the timeline glow layer (`ui/tracks/activityRender.ts`), the track header's level glow (`TrackHeader.tsx`), meters (ballistics `domain/mixer.ts: stepMeter`, state `state/levels.ts`, picture `ui/common/Meter.tsx`; readings that already fall at their source, like the input level, go through `plainLevel`), the beat lights and the Play button pulse (`ui/transport/BeatLights.tsx: createBeat`), the welcome screen's waveforms (`ui/WelcomeBackdrop.tsx`) and the same waves in the transport bar, which swell and tremble with the master meter's peak (`ui/transport/HeaderWaves.tsx`; both draw with `ui/common/waves.ts: drawWaves`, `energy` 0 is the calm drift), the master visualizer ([docs/features/master-visualizer.md](../../../docs/features/master-visualizer.md)). A new per-frame drawing reads `smoothPlayhead` and keeps its per-frame work small, like the glow layer (its own transparent canvas, only the clips under the playhead) — never a heavy canvas.

**Large components are split by role**: the assembling component holds the view state, drawing goes to `*Render.ts`, mouse handling to `*Pointer.ts`/`pointer.ts`, geometry to `*Layout.ts`. The assemblies, each listing its parts in its header: `pianoroll/PianoRoll.tsx`, `graph/GraphView.tsx`, `samples/SampleEditorView.tsx`, `automation/PatternEditor.tsx` (with `AutomationClipPanel`), `drums/DrumPartDialog.tsx`. The backend mock is organized the same way ([src/mock/CLAUDE.md](../mock/CLAUDE.md)).

**Shared techniques go into `ui/common`**, not copied into a section (a canvas matched to screen density, the mouse point, a theme color) — as did the selection box (`canvas.ts: drawSelectionBox`), the visible-window test (`scrollWindow.ts: inWindow`), the bars stepper (`BarsStepper`), the looping audition of the drum and chord part dialogs (`loopPreview.ts`) and track colors (`trackColors.ts: trackColorOf`/`clipColorOf`).
