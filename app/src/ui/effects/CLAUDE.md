# `src/ui/effects/` — effect editors and their live graphs

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [sidechain](../../../../docs/features/sidechain.md).

**Live effect visuals** (every built-in effect's editor shows a graph of what it does, drawn from its params so it follows the knobs at once even while stopped, with the node's live sound over it that fades out when playback stops; the Graph page's signal path view shows every effect along a path at once). Contract: `NodeScope::watch_nodes(nodes)` and `node_windows(seen: [NodeCursor]) → [NodeWindow { node, watch, end, input, output, sample_rate }]` (`daw-contracts/src/engine.rs`, `Controls.node_scope`; `NODE_WINDOW_FRAMES` = 4096 mono frames per node, about 85 ms at 48 kHz with bins of about 12 Hz — 2048 would leave the 20–150 Hz end of the EQ graph a handful of bins; `MAX_WATCHED_NODES` = 16). `input` is what came into the node before it changed the sound (before the effect, the same as `output` while bypassed; before the fader for sources, buses and the master), `output` what it sent on, over the same frames. Why the input too: most pictures compare the two — a distortion draws its output against its input, a compressor, limiter or gate measures the input against its threshold (a closed gate's output is silence), a delay lights its echoes by the input that feeds them, a reverb finds its own sound as `output − input × (1 − mix)` — and none of it can be recovered from the output of a nonlinear or dynamic effect. The watched nodes are a set for the whole app, replaced as a whole: the interface sends the union of every picture it shows, so two pictures of one node cannot stop each other, and a node that stays in the set keeps its window while a joining one gets a new `watch` number and starts from silence. Ids beyond the first 16 distinct ones are not watched. Each read is one batched call for all watched nodes, and it is incremental: a reader passes back each node's `watch` and `end` from its previous window (`NodeCursor`) and gets only the frames after it (a whole window for a new watch, no cursor, or a reader more than a window behind), so the traffic stays near the audio rate itself (two lanes × the sample rate per node) instead of two whole 4096-frame windows per node 30 times a second; cursors live with the reader, so the read changes nothing in the engine and several readers (the interface, an AI client over MCP) do not disturb each other. It is its own contract, not more `EngineStats`: watching nodes is a job of its own, and the planned `EngineLink` split gives telemetry its own traits anyway. Engine: `daw-engine/src/scope.rs: NodeTap` in `Telemetry`, `MAX_WATCHED_NODES` preallocated slots, each two `Lane`s of atomics (input, output) moved by one frame count (`end`); `GraphMixer::process` offers every node's input before the effect or fader (`tap.input`, written at the frames the output will take, the count does not move) and its output after (`tap.output`, moves the count). On the audio thread a node costs one atomic load while nothing is watched and a scan of the 16 slots otherwise; only watched nodes are copied, never allocating. The control side (`watch`, `windows`) keeps the watch numbers under a mutex the audio thread never takes. The shared count keeps a node's two windows paired frame by frame even when the set changes between the two writes; a read that lands between them sees the newest input in place of the oldest frame of a whole window, and a slot freed and retaken during a segment may keep a few samples of the old node — both harmless for a picture. The window is mono (the middle of the channels): a hard-panned sound reads up to 6 dB below what an effect's detector sees, and a sidechain key is not captured (a keyed compressor or gate shows its own input; the gain reduction is still the engine's). RPC `audio.watchNodes { nodes }` / `audio.nodeWindows { seen }` (`daw-rpc/src/audio.rs`), actions `audio.watchNodes` / `audio.nodeWindows`, mock `mock/handlers/audio.ts` with `mock/liveSound.ts` (the set, watch numbers and frame counts that run with the clock; the same music for input and output: the mock runs no effects, so an EQ's spectrum ignores its bands and a distortion's trace lies on the 1:1 line there). Frontend: one registry for the app, `state/nodeSounds.ts` (`session.nodeSounds`): pictures `listen(node, hear)`; while anything listens it polls every 33 ms (`createPoller`), tells the engine the set when it changed (and again when a reply lacks a node: another client replaced the set), reads all windows in one call with its cursors, keeps each node's latest 4096 frames and hands every listener `{ input, output, sampleRate, dt, now }`; the last listener leaving stops polling and empties the set, a failed read (the action shows a toast) stops it until the next picture opens. Nodes beyond the first 16 listened to sound silent. `ui/effects/nodeSound.ts: listenToNode(node, hear, onStop)` is the pictures' side: it listens while the component lives and again for another node when it switches (a memo on the node id). Shared pure math: `domain/liveLevels.ts` (peak and RMS of the newest 35 ms, a scrolling history of readings, a fast-up/slow-down follower that makes pictures fade instead of blink off), `domain/plot.ts` (view size, dB → height, SVG line and area paths), `domain/frequencyAxis.ts` (the 20 Hz–20 kHz log axis and grid of the EQ and filter graphs), `domain/biquad.ts` (the RBJ biquad mirror of `biquad.rs` with complex responses, for every graph of a biquad effect), `domain/bandGains.ts` (the engine's band gains held for the band-split graphs). Each effect's shape is a pure module that **mirrors** its Rust DSP (each Rust module names its mirror; change both sides together), and the graph is a component in `ui/effects/` chosen by kind in `EffectGraph.tsx` (used by `EffectPanel` and the signal path view):
* `eq` → `EqGraph.tsx` + `LiveSpectrum.tsx`: the response curve (`eqCurve.ts` mirrors `eq.rs`, on the biquad mirror `biquad.ts` of `biquad.rs`, shared by every graph of a biquad effect) with draggable band handles over the live spectrum of the output, like Pro-Q by default (what you hear, so a boost or cut reshapes the spectrum under the curve). Spectrum math `domain/spectrum.ts`: the master visualizer's Hann-windowed FFT (`visualizer.ts: magnitudes`); 150 points spread evenly over the log axis, each the power mean of its bins where it covers two or more and the value between the two nearest bins below that; a +4.5 dB/octave tilt around 1 kHz (music falls about that much, so the highs do not hug the floor); its own 0…−90 dBFS scale (a curve's gain scale is far too narrow for a spectrum); smoothing that rises in ~30 ms and falls in ~250 ms.
* `filter` → `FilterGraph.tsx`: the SVF response (`filterCurve.ts`, mirrors `filter.rs`: the analog prototype under the bilinear transform, k = 1/Q, the band-pass normalized, the mix) on +24…−36 dB over the same `LiveSpectrum`; one handle at the cutoff — drag sets the cutoff and, for low- and high-pass, the resonance (the peak's height is Q in dB), the wheel sets the resonance, double-click resets both.
* `compressor`, `limiter`, `gate` → `DynamicsGraph.tsx` (geometry `dynamicsGraph.ts`; curves `compressorCurve.ts` mirrors `dynamics.rs: GainComputer::reduction`, `limiterCurve.ts` the input gain and ceiling, `gateCurve.ts` the threshold, 6-dB hysteresis and depth as two branches, the way up and the way down). Left, the transfer curve with the thresholds dashed and a dot at (input level, output level) of the newest sound, which leaves the curve during attack and release; right, the last 3 s of input level (line), output level (area) and the engine's gain reduction (from `tick.reductions`, unheld, hanging from the top on the same dB scale) against the thresholds; under them the held GR meter (`ReductionMeter`) and, for the gate, Open/Closed from its reduction (open while it takes less than half of its depth).
* `distortion`, `saturator`, `tape` → `ShaperGraph.tsx` (`shaperCurve.ts` mirrors `Shape::apply`, the saturator's `shapes` with drive, mix and output, and the tape's `soft_knee` with its modes' knee and offset and the drive compensation; the tone filter, oversampling, DC blockers, the tape's head bump and roll-off and the console's crosstalk shape the sound over time and are left out of the curve). Left, the transfer curve (input sample → output sample) with the newest 1024 frames traced over it as an X-Y scope — a pure shaper retraces its curve, the tone filter opens it into a loop; right, the input wave (dim) and the output wave (bright) from the latest rising zero crossing (`visualizer.ts: latestTraceStart`). The last trace stays and fades when the sound stops.
* `delay` → `DelayGraph.tsx` (`delayTaps.ts` mirrors the `SYNC_QUARTERS` lengths, the time from the tempo — `tick.tempo`, like the engine's `BlockTiming` — or from ms, feedback per repeat, ping-pong starting on the left, `mix_over_dry`): the dry bar and up to 12 echoes above −48 dB as outlined bars on a time line with the beats dotted; live, each bar fills with the input level of one, two… delays ago, so a hit runs along the echoes and they die away one by one after playback stops.
* `chorus` → `ChorusGraph.tsx` (`chorusSweep.ts` mirrors the LFO: one sine at `rate`, the right voice a quarter turn ahead, `delay ± depth`): both voices' delay over the last 2 s scrolling with the LFO inside the depth band; the dots at "now" and the band light up with the output level. The engine does not report its LFO phase, so the picture turns its own at the same rate: right speed and range, not the engine's exact moment.
* `reverb` → `ReverbGraph.tsx` (`reverbTail.ts` mirrors Freeverb's comb feedback `0.7 + 0.28·room`, the damping lowpass `0.4·damp` and the mean comb length: RT60 at f = 3 × pass time / −log10(feedback × lowpass gain at f)). One time line with "now" a third of the way in: the last 2 s of dry level (line) and the reverb's own level (area, `output − input × (1 − mix)` — exact, the dry part of `Reverb::process`), then the decay fan from "now" — an outline from 0 dB falling to −60 dB in the RT60 of the lows (upper edge) and of 5 kHz (lower edge, faster with damping), and the same fan filled from the reverb's level now — with the lows' RT60 in the corner.
* `multiband` → `MultibandGraph.tsx` (`multibandCurve.ts` mirrors `multiband.rs` and `crossover.rs`: the ordered splits, each band's chain of Linkwitz–Riley halves and later all-passes as complex responses on the biquad mirror, three bands as the top two summed, solo and bypass). On the frequency axis over the live spectrum: the shapes of the bands in use (thin), the whole effect's response with every band at its gain minus its live reduction (bright: what the bands do to the sound now — the sum is flat while nothing compresses), and each band's reduction hanging from the top of its stretch with its value. The live reduction is the engine's band gains (`tick.bands`, held by `createBandGains`), not measured from the window. Split lines drag like EQ handles (double-click resets); under each band its number and S/B chips toggle `band<n>_solo`/`band<n>_bypass`.
* `dynamic_eq` → `DynamicEqGraph.tsx` (`dynamicEqCurve.ts` mirrors `dynamic_eq.rs`: four peaking biquads in a row, each at its gain times how far it is engaged). On the EQ's axes over the live spectrum: the response with every band at its full gain (dashed: as far as it can go) and with the bands where they are now (bright), and at each band a bar from 0 dB to its live gain — the engine's band gains (`tick.bands`, held by `createBandGains`), so the curve breathes with the sound. One handle per band at (frequency, full gain): drag sets both, the wheel sets Q, double-click resets the band; a band with gain 0 is dimmed.
* `de_esser` → `DeEsserGraph.tsx` (`deEsserCurve.ts` mirrors `de_esser.rs`: the 0-dB band-pass at Q 1; split-band `1 − (1 − g)·band`, wideband `g`, listen the band alone). On the frequency axis over the live spectrum: the detected band shaded, the response at the full range (dashed: as deep as it goes) and the response now from the engine's gain reduction (`session.reductions`, held), so the dip at the band follows each "s"; under it the gain reduction meter and, while listening, a "listening to the band" note. The band's handle drags its frequency (double-click resets).
* `transient` → `TransientGraph.tsx` (`transientShape.ts` mirrors `transient.rs`: the same followers, times, cap and smoothing run on the envelope of a model hit). Left, the model hit (20 ms silence, an instant rise, a 120-ms fall) and the shaped hit over 400 ms, recomputed at 8 kHz on every knob move, so attack shows at its start and sustain in its tail. Right, the last 2 s of the live sound as envelopes in 5-ms steps — input (line) and output (area): each reading cuts the newest `dt × rate` frames of the window into 5-ms peaks — and under them the strip of output minus input (±12 dB around the middle line): how far the shaper lifted or lowered each moment.
* `linear_eq` → `LinearEqGraph.tsx`: the EQ's own graph (`EqGraph`, the same params and so the same curve — `eqCurve.ts` is its magnitude — handles and live spectrum) with the latency it adds at the stream's rate in the top corner (`linearPhase.ts` mirrors `kernel_len` and `Convolver::latency`; the rate from `ui/common/streamRate.ts`).

A new effect's picture: a pure mirror module in `domain/` (settings by param names with `catalog.ts: namedParams`, so a changed catalog shows no graph rather than a wrong one), a component in `ui/effects/` that calls `listenToNode` once if it needs the live sound, a `Match` (or a table entry) in `EffectGraph` (and its kind in `hasEffectGraph`), a note in the Rust module naming its mirror. Tests: `daw-engine/src/scope.rs` (lanes and slots: only watched nodes, pairing, cursors of the same watch get only new frames, a staying node keeps its window and a joining one starts from silence, the 16-node limit, a switch between the writes), `daw-engine/src/tests/scope.rs` (input and output of an effect, bypass, a whole path at once with a bus before and after its fader, cursors, leaving the set), `daw-rpc/tests/all/audio.rs`; the frontend has no tests yet.
