# `src/ui/settings/` — the Settings page

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [errors](../../../../docs/features/errors.md).

**The "Settings" page** (the gear at the bottom of the activity bar): `SettingsView.tsx` — the list of sections and the open one. Which section is open is `session.ui.settingsSection`, navigation is the intent `session.ui.showSettings(section)` (used by the menu items "Audio…", "Plugins…", "Error log…"). Shared building blocks are in `SettingRow.tsx` (`SectionTitle`, `SettingGroup`, `SettingRow`, `Toggle`, `CopyButton`); each section is its own file: `ProfileSection`, `AppearanceSection`, `ProjectSection` (its summary is `domain/projectStats.ts`), `AudioSection`, `MidiSection` (`actions/midiInput.ts`, knobs on parameters — `actions/midiLearn.ts`), `PluginsSection` (filtering — `domain/plugins.ts: filterPlugins`), `SoundsSection` (pack folders), `ShortcutsSection`, `LogSection` (version, path to `errors.log`, recent entries). A new section: a value in `SettingsSection` (`state/views.ts`), a row in `SECTIONS` in `SettingsView.tsx`, and the section file.

**Audio settings** (`AudioSection.tsx`; "Project" → "Audio…" opens it): the section only gathers the form; `actions/audio.ts: apply(form)` validates the fields and reports the result. Parsing and limits are pure functions in `domain/audioSettings.ts`, shared with the mock. The input is watched only while "Test input" runs (`state/poller.ts: createWatchedPoll`). Mock: `mock/handlers/audio.ts` (a "broken" device that never opens, a pseudo-sine input level).
