# `src/ui/settings/` — the Settings page

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [errors](../../../../docs/features/errors.md).

**The "Settings" page** (the gear at the bottom of the activity bar, `ui/settings/`): `SettingsView.tsx` — the list of sections on the left and the section on the right; which section is open is `session.ui.settingsSection`, navigation is the intent `session.ui.showSettings(section)` (used by the menu items "Audio…", "Plugins…", "Error log…"). Shared building blocks are in `SettingRow.tsx` (`SectionTitle`, `SettingGroup`, `SettingRow`, `Toggle`, `CopyButton`); each section is its own file: `ProfileSection` (author, projects folder, "open last project", autosave), `AppearanceSection` (theme, accent, zoom, track height, hints), `ProjectSection` (name, path, tempo, time signature, metronome, record quantize, summary — `domain/projectStats.ts`), `AudioSection`, `MidiSection` (devices, track, connection — `actions/midiInput.ts`; the backend does not report what is connected, so the action remembers the connection made in this run; knobs on parameters — `actions/midiLearn.ts`), `PluginsSection` (scan folders, the `plugins.list` table with filtering via `domain/plugins.ts: filterPlugins` and a "Disabled" toggle — `plugins.setDisabled`, "Scan" and the last scan result `plugins.lastScan()` with "failed" marks), `SoundsSection` (pack folders `sounds.sources/addSource/removeSource`), `ShortcutsSection`, `LogSection` (version via `AppShell.version`, path to `errors.log`, recent entries). A new section: a value in `SettingsSection` (`state/views.ts`), a row in `SECTIONS` in `SettingsView.tsx` (with the section component), and the section file.

**Audio settings** — the "Audio" section of the settings page (`ui/settings/AudioSection.tsx`; the menu item "Project" → "Audio…" opens it): output/input devices ("Default" = null), buffer size, recording latency and "Test input". Actions: `actions/audio.ts` (`devices/settings/status/apply/watchInput/inputLevel`); `apply(form)` parses the fields itself (`parseRecordLatency`, `parseBufferFrames` and the limit `MAX_RECORD_LATENCY_MS` shared with the mock — `domain/audioSettings.ts`): an invalid latency — a toast, a device error — a toast via `ctx.run`, success — "Audio switched to …". Input is turned on with `watchInput(true)` only for the duration of the test and turned off when the test ends or the section is left (`state/poller.ts: createWatchedPoll`). The buffer sizes allowed by the device's range and the latency are pure functions in `domain/audioSettings.ts`. Mock: `mock/handlers/audio.ts` (the "Broken…" device never opens, the input level is a pseudo-sine).
