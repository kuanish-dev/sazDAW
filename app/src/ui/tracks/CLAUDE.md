# `src/ui/tracks/` — the Tracks page: timeline, headers, automation

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [automation](../../../../docs/features/automation.md), [bounce](../../../../docs/features/bounce.md), [cue](../../../../docs/features/cue.md), [preferences](../../../../docs/features/preferences.md), [recording](../../../../docs/features/recording.md), [sounds](../../../../docs/features/sounds.md), [tempo-map](../../../../docs/features/tempo-map.md).

Clip selection on the timeline: the set of selected clips lives in the session (`session.selection.clips()`; `clip()` means "exactly one") and is changed only by the intents `selection.selectClips(ids, track?)` / `clear()`. The pure logic (marquee, Shift selection, group move limited by rows and track kind, "did the edit change anything") is in `domain/clipSelection.ts`; the mouse is in `ui/tracks/timelinePointer.ts` (the drag draft `ClipDraft` is drawn in `timelineRender.ts` and committed with a single `actions.clips.commitMany`; Alt copies via `copy`). On release the clip actions (`commitMany`, `edit`, `trimStart`) show the edit in the project at once (`patchProject`) and the pointer keeps the draft until the action is done: otherwise the clip is drawn at its old place for a frame, between the draft going away and the refreshed project arriving. The group API methods (`clips.editMany/removeMany/copy`) are one undo step, and room (overlaps and crossfades) is checked against the resulting state; their mock is `mock/handlers/clipGroups.ts` with shared rules in `mock/clipRules.ts`. The clip clipboard (Ctrl+C/V/D) is held by the actions layer, the keys are in `state/clipKeys.ts`; arrow keys moving by one grid step are not done yet (the grid lives in the timeline panel, not in the session).

Audio clip waveform on the timeline (as in Ableton): `ui/tracks/clipWaves.ts` requests the envelope of the whole sound once per sample — one cache for the Tracks page, provided by `TracksView` (`ClipWavesContext`) to the timeline and the take lanes (`sampleEditor.waveform`, ~200 bins per second; the sound's length comes from `samples.sampleInfo`, where the sample list is cached until `project.samples` changes) and returns the clip's columns on each draw request; the pure math "sample envelope → a [min, max] pair per clip pixel, taking offset, length and tempo into account" is in `domain/clipWave.ts`; `drawWave` in `timelineRender.ts` draws it under the clip name. Columns are cached by clip × width × tempo (drawing happens on every playback frame); until the envelope arrives the clip is drawn without a waveform, and once it arrives the timeline redraws itself (the cache is a signal).

**Track row heights.** Each track row can be resized on its own: drag the bottom edge of the track header (`ui/tracks/trackResize.ts`; double-click returns the track to the Appearance setting, ↑/↓ on the focused edge change it by 8 px). The height is `Track.height` in the project (pixels, `MIN_TRACK_HEIGHT..=MAX_TRACK_HEIGHT` = 36…400; `None` follows the setting): like the track color it is part of the song's layout and saved with it, set by `TrackControl::set_height` (RPC `tracks.setHeight`; keyed edits, so a resize is one undo step "Track height"; outside the range — `TR-212`). While dragging, `tracks.resize` changes only the screen copy (`ctx.patchProject`), `tracks.setHeight` on release saves it. Since rows differ in height, all row geometry goes through `domain/rowLayout.ts`: `rowLayout(rows, default)` gives every row's top (a track its own height, folder and automation lane rows the default), and `rowTop`, `rowHeight`, `rowAt`, `clampRow`, `timelineHeight`, `insertSlot` work on it — headers (`TracksView`), the canvas (`timelineRender`, `laneRender`, `clipRect` in `timelineLayout.ts`), the mouse (`timelinePointer`, `lanePointer`), sound drops (`timelineDrop`) and reordering (`trackReorder`) share one layout, so they stay aligned. A row shorter than the mixer strip (84 px) shows only the header's name line, with mute/solo in it (`TrackHeader.tsx`). The ☀/☾ button on the transport bar changes the same theme setting.
