# `src/ui/tracks/` — the Tracks page: timeline, headers, automation

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [automation](../../../../docs/features/automation.md), [bounce](../../../../docs/features/bounce.md), [cue](../../../../docs/features/cue.md), [preferences](../../../../docs/features/preferences.md), [recording](../../../../docs/features/recording.md), [sounds](../../../../docs/features/sounds.md), [tempo-map](../../../../docs/features/tempo-map.md).

**Clip shapes.** On the timeline every clip-shaped thing — note, audio and automation clips, crossfades, the drop ghost — takes its rectangle from `timelineLayout.ts: spanRect`, pixels → ticks from `tickAtX`, and its look from `clipFrame.ts: drawClipFrame` (the clip draws its own content inside), so they line up.

**Clip selection.** The set of selected clips lives in the session (`session.selection.clips()`; `clip()` means "exactly one") and is changed only by the intents `selection.selectClips(ids, track?)` / `clear()`. The pure logic (marquee, Shift selection, group move limited by rows and track kind) is in `domain/clipSelection.ts`; the mouse is `timelinePointer.ts`: the drag draft `ClipDraft` is drawn by `timelineRender.ts` and committed with one `actions.clips.commitMany` (Alt copies via `copy`). On release the clip actions show the edit in the project at once (`patchProject`) and the pointer keeps the draft until the action is done, so the clip never flashes at its old place for a frame. The group API methods (`clips.editMany/removeMany/copy`) are one undo step each, and room (overlaps and crossfades) is checked against the resulting state; their mock is `mock/handlers/clipGroups.ts` with shared rules in `mock/clipRules.ts`. Clip keys are `state/clipKeys.ts`; arrow keys moving by one grid step are not done yet (the grid lives in the timeline panel, not in the session).

**Audio clip waveforms** (as in Ableton): `clipWaves.ts` requests each sample's whole envelope once (`sampleEditor.waveform`) into one cache for the Tracks page, provided by `TracksView` (`ClipWavesContext`) to the timeline and the take lanes, and caches each clip's columns because drawing happens on every playback frame; the pure math "envelope → a [min, max] pair per clip pixel" is `domain/clipWave.ts`, the drawing `timelineRender.ts: drawWave`. Until the envelope arrives the clip is drawn without a waveform; the cache is a signal, so the timeline redraws itself when it arrives.

**Track row heights.** Each row is resized on its own by the bottom edge of its header (`trackResize.ts`). The height is `Track.height` in the project (`None` follows the Appearance setting): like the track color it is part of the song's layout and saved with it, set by `TrackControl::set_height` (RPC `tracks.setHeight`, one undo step; out of range — `TR-212`). While dragging, `tracks.resize` changes only the screen copy (`ctx.patchProject`); `tracks.setHeight` on release saves it. Since rows differ in height, all row geometry goes through `domain/rowLayout.ts` — headers (`TracksView`), the canvases (`timelineRender`, `laneRender`, `timelineLayout.ts`), the mouse (`timelinePointer`, `lanePointer`), sound drops (`timelineDrop`) and reordering (`trackReorder`) share one layout, so they stay aligned. A row lower than a mixer strip (`TrackHeader.tsx: STRIP_MIN_HEIGHT`) shows only the header's name line, with mute/solo in it.
