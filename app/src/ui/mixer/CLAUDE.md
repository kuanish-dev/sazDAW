# `src/ui/mixer/` — the Mixer page

Map of the whole code: [ARCHITECTURE.md](../../../../ARCHITECTURE.md). Cross-layer features it takes part in: [master-meter](../../../../docs/features/master-meter.md), [master-visualizer](../../../../docs/features/master-visualizer.md).

**The "Mixer" page** (the tab between "Graph" and "Samples", `ui/mixer/`): track strips in track order, then buses, with the master pinned to the right edge. `MixerView.tsx` — layout and the open effect; `ChannelStrip.tsx` — a strip: name (double-click to rename: a track via `tracks.rename`, a bus via `graph.renameNode`), kind, the channel utility (`ui/common/ChannelUtility.tsx`, see "Channel utility" ([docs/features/channel-utility.md](../../../../docs/features/channel-utility.md))), pan, fader, meter from `session.levels` for its node, M/S; a click selects the track; `StripRouting.tsx` — inserts, sends, output; `EffectPopover.tsx` — the insert's parameters using the same `EffectPanel` as the graph inspector, and "Remove" (`removeEffectKeepPath`). The graph is free-form, so what counts as an insert, an output and a send is decided by the pure `domain/mixerStrips.ts` (a convention): the signal path is the node's first normal "post-fader" edge; an insert is an effect on that path that nothing else feeds into (a compressor shared by several tracks is already an output, not an insert); from the last insert (`tail`), the first "post-fader" edge is the output, and all other normal edges of the node and its inserts are sends (a "pre-fader" edge is always a send). The master's inserts are effects that all of its input passes through (and that are not inserts of other strips). "＋ Effect" is `graph.insertEffectAt(tail)` (right after the tail; for the master, which has no output, right before it — the same action as "＋ Effect" in the graph), "＋ Send" is `connect(tail, bus, 0.5)`, PRE/POST is `setEdgePreFader` (only for a send from the node itself: the backend does not allow it from an effect), the output is `graph.routeOutput(tail, to)`: `setOutput` keeps only the "pre-fader" sends, so the action re-creates the "post-fader" sends (several undo steps). Send rows use `Index`, not `For`: edges have no id, after a re-read they are new objects, and `For` would re-create a knob in the middle of a drag. A new strip column is a field in `StripModel` and a component in `StripRouting`/`ChannelStrip`.
