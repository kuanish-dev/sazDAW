# `src/i18n/` — interface languages

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [errors](../../../docs/features/errors.md).

**Interface languages (frontend).** English is the default, Russian the second language; the choice is `Preferences.language` (`"en" | "ru"`, Settings → Appearance → "Language / Язык"), applied live without a restart. Infrastructure — `src/i18n/`: `en.ts` is the source of truth for keys (a plain nested object of strings and functions for parameters/plurals, sections by interface area), `ru.ts` is typed `Messages` (a missing or extra key fails `tsc`), `index.ts` gives the reactive `t()` (dictionary of the current language; a read in JSX or a memo re-renders on switch), `setLanguage`, `LANGUAGE_CHOICES`, and `plural(n, forms)` (`plural.ts`: `[one, other]` for English, `[1, 2–4, 5+]` for Russian). i18n is a leaf: it imports no layer (Biome rule for `src/i18n/**`), so every layer may import it — `domain` reads `t()` for labels and input hints, the mock uses it so the names it creates and its catalog follow the language like the real backend. The mock fails exactly like the backend: `mock/errors.ts: fail(code, params)` builds the same `{ code, params, message }` with a code from the Rust registry (`crates/daw-contracts/src/codes/`) and its English template copied into the mock's small `ENGLISH` table, so the interface translates mock errors by code too (a new mock failure: find the backend code for the situation, copy its template into `ENGLISH`, `throw fail(...)`). The language is set by `state/appearance.ts` from preferences (cached in `localStorage` with the theme to avoid an English flash, and written to `<html lang>`); after a language change `actions/preferences.ts` re-reads the catalog, because the backend writes its catalog labels and pattern names in the current language and the frontend shows them as is; errors arrive as codes (`daw_contracts::ContractError`, see "Errors as codes" ([docs/features/errors.md](../../../docs/features/errors.md))) and are shown in the current language by `app/src/i18n/errors/`. Native dialog titles and buttons are passed from the frontend through `t()`. Adding a string: a key in `en.ts`, the same key in `ru.ts`, `t().section.key` at the place of use (read it at render time, not once at setup, or it won't switch). Data identifiers (kinds, ids, enum values) are never translated.
