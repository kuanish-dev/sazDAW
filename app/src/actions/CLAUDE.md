# `src/actions/` — actions

`src/actions/`: one interface per job plus a factory implementation — `TransportActions` (play, position, cue, the loop region, song loop, metronome), `HistoryActions` (undo/redo), `TempoActions` (song tempo and time signature), `ProjectActions` (project files and the warnings opening one leaves), `AudioExportActions` (rendering the song to a file), `StartupActions` (what the app says and asks once after the first project read: open warnings, a plugin crash, autosave recovery), `TracksActions`, `FoldersActions`, `MarkersActions`, `ClipsActions`, `NotesActions`, `NoteEffectsActions`, `AutomationActions` (with the pattern point clipboard), `GraphActions`, `StageActions` (the virtual stage: placing channels live, the room) (which sounds are in the project), `SampleEditorActions` (everything done with one sound), `SoundPlacementActions` (sound → timeline/track/editor), `SoundBrowserActions` (project folder and packs), `PreviewActions`, `LiveActions`, `LogActions`, `AudioActions` (devices, the visualizer and node windows, the live master meter and the mono check), `NoteRecordActions` (note recording: arming and the record quantize), `AudioRecordActions`, `PluginsActions` (list, scan and the result of the last scan), `PluginEditorActions`, `DrumsActions`, `ChordsActions`, `MidiInputActions` (live MIDI input), `MidiLearnActions` (knobs on parameters), `PreferencesActions` (app preferences), `AboutActions` (version), `BounceActions` (bouncing a track to audio), `TemplatesActions` (project templates), `PresetsActions` (instrument and effect presets); assembled in `actions/index.ts`. Shared pieces: `ParamTouch` (`paramTouch.ts`: live automation writing hears every parameter move), `saveUnderName` (`namedSave.ts`: presets and templates), `addTracks` (`newTracks.ts`). They decide how to show errors and what to re-read. What an action gets is split by role in `actions/context.ts` — `Backend` (api, dialogs, shell), `Calls` (`run`/`attempt`/`exec`/`withBusy`, `toast`, `showFailure`), `ProjectCopy` (project, status, catalog, re-read, `patchProject`), `PlaybackPosition` (`tick`), `PreferencesCopy`, `View` (tab, automation selection, `showCreated`: re-read, then select what an action created — selecting first would be undone, because the selection gives way to items the copy doesn't have yet), `RecordingFollow` — and each factory names only the roles it uses (`ctx: Backend & Calls & ProjectCopy`); `ActionContext` is all of them together

Knows about: `api`, `domain`, the roles in `actions/context.ts`.
