# `src/state/` — the session state

`src/state/`: `session.tsx` declares `Session` — what the UI may read and ask for, grouped by role — and only assembles it from parts, one file each: `projectSync` (project copy, status, catalog; on a change it takes in only the changed parts, `project.changes`, and re-reads the whole project after a refused call), `playback` (`tick` and the positions for drawing), `selection` (track, clips, sample, automation; changed only by its intents), `views` (tab, settings section, instrument window), `drumKit`, `notifications` (toasts, `showFailure`), `preferences`, `appearance` (theme, accent, zoom, row height, hints, language), `actionContext` (assembles the action roles of `actions/context.ts`), `levels` (meters), `nodeSounds` (the live sound of the nodes the effect pictures show: one batched read for the app), `recordingStatus` and `poller` (`createWatchedPoll`: a backend capture that is open only while it is polled), `keyboardPiano`. Window listeners that `App.tsx` installs on mount: `globalKeys` (with `clipKeys`), the keyboard piano and `touchRelease`. The startup sequence — preferences, the first project read, then `actions.startup.afterFirstRead` — ends `createSession`

Knows about: `RpcClient`, dialogs, actions, domain.

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [automation](../../../docs/features/automation.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-visualizer](../../../docs/features/master-visualizer.md), [preferences](../../../docs/features/preferences.md), [recording](../../../docs/features/recording.md), [sidechain](../../../docs/features/sidechain.md).

**Window keys** are the table in `state/globalKeys.ts` (`installGlobalKeys`); the clip keys of the Tracks page are `state/clipKeys.ts`. The three ways a part of the window keeps keys from them (`data-owns-space`, `data-owns-keys`, `claimSpace`) are listed in the header of `globalKeys.ts`; a new panel with its own keys picks one of them. The clipboards live in the actions layer: notes in `actions/notes.ts` (`copy`/`canPaste`/`paste`), automation points in `actions/automation.ts` (`copyPoints`/`pastedPoints`), clips in `actions/clips.ts`.

**Keyboard shortcut help** (Settings → `ui/settings/ShortcutsSection.tsx`) is built from the same tables the keys work from (`globalKeysHelp`, `clipKeysHelp`, `PIANO_ROLL_KEYS_HELP`, `keyboardPianoHelp`, `GRAPH_KEYS_HELP`, `PATTERN_KEYS_HELP`; the shared row type and key labels are in `domain/shortcuts.ts`). A new key is a row in the table next to its handler; the help shows it automatically.

**Playback position for drawing** (`state/playback.ts`). Canvases (timeline, piano roll, steps, automation, sample editor) read `session.playhead()` / `previewPlayhead()`, not `tick()`: the tick arrives ~30 times per second even when stopped (meters are live), the derived positions fire only on a change. Light per-frame elements — the timeline cursor (a separate element moved with `translateX`, so the canvas is not redrawn during playback), the glow layer, the beat lights — read `session.smoothPlayhead()`, extrapolated between ticks by the pure `domain/playhead.ts`; it waits at the end of `tick.wrap` (the loop region or the song, see [song-loop](../../../docs/features/song-loop.md)) until the jump arrives. A new canvas that needs the position takes it from here.

**Long canvases** inside a scroll area (the timeline rows, the ruler strip and automation lanes) are only the size of the visible window (`ui/common/scrollWindow.ts`; why: its header). Drawing is in whole-timeline coordinates shifted by the window's left edge; the mouse is measured against the full-size wrapper (`surface`), so gestures know nothing about the window. A new long canvas is built the same way.

Meter levels are computed once for the whole app by `state/levels.ts` (`session.levels`): the track headers, the mixer and the graph read them.
