# `src/state/` — the session state

`src/state/`: `session.tsx` declares `Session` — what the UI may read and ask for, grouped by role — and only assembles it from parts: `projectSync` (project copy, status, catalog, re-reading), `playback` (`tick`, `playhead`, `previewPlayhead`, `smoothPlayhead`), `selection` (track, clips, sample, automation; intents `selectTrack`/`selectClips`/`clear`/`selectSample`), `views` (what the window shows: tab, settings section, instrument window), `drumKit` (the drum sound choice between builds), `notifications` (toasts with `showFailure`, and "Notes recorded" after a take), `preferences` (the copy of the app preferences), `appearance` (theme, accent, zoom, row height, hints), `actionContext` (assembles the action roles: `run`/`attempt`/`exec`/`withBusy`, `showCreated`), `levels` (meters), `nodeSounds` (the live sound of the nodes the effect pictures show: one watched set and one batched read for the app), `recordingStatus` and `poller` (polling; `createWatchedPoll` — a backend capture that is open only while it is polled), `keyboardPiano`; window listeners that `App.tsx` installs on mount: `globalKeys` + `clipKeys` (window keys) and `touchRelease` (a mouse or key up anywhere releases live-written controls). The startup sequence — preferences, the first project read, then `actions.startup.afterFirstRead` — ends `createSession`

Knows about: `RpcClient`, dialogs, actions, domain.

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [automation](../../../docs/features/automation.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-visualizer](../../../docs/features/master-visualizer.md), [preferences](../../../docs/features/preferences.md), [recording](../../../docs/features/recording.md), [sidechain](../../../docs/features/sidechain.md).

Window keys are the table in `state/globalKeys.ts` (`installGlobalKeys`): Space, ⌘Z/⇧⌘Z/⌘Y, ⌘S/⇧⌘S, ⌘O, ⌘N and, on the "Tracks" page, the clip keys. A part of the window keeps keys from them in one of three ways (listed in that file's header): input fields and the sound browser list (`data-owns-space`) keep keys to themselves while focused; a panel with its own keys (`data-owns-keys`) swallows what it handled (below); and a view that gives Space its own meaning while it is shown, whatever has focus — the sample editor (preview, not transport) — calls `claimSpace`, a capture-phase listener that stops the window keys. A panel with its own keys is marked `data-owns-keys`, takes focus on press and suppresses what it handled itself (`preventDefault`): this way Delete/Esc/⌘A/C/V/D in the piano roll do not touch the timeline clips, while the global keys still work over it. The note clipboard (⌘C/V) is in `actions/notes.ts` (`copy`/`canPaste`/`paste`), the automation point clipboard in `actions/automation.ts` (`copyPoints`/`pastedPoints`).

**Keyboard shortcut help** is built from the same tables the keys work from: `GLOBAL_KEYS_HELP` (`state/globalKeys.ts`), `CLIP_KEYS_HELP` (`state/clipKeys.ts`), `PIANO_ROLL_KEYS_HELP` (`ui/pianoroll/editing.ts`), `GRAPH_KEYS_HELP` (`ui/graph/GraphCanvas.tsx`), `KEYBOARD_PIANO_HELP` (`domain/keyboard.ts`), `PATTERN_KEYS_HELP` (`ui/automation/PatternEditor.tsx`); the shared row type and key labels are in `domain/shortcuts.ts`. A new key is a row in the table next to its handler; the help shows it automatically.

Playback position for drawing: `session.playhead()` (`null` while the transport is stopped) and `session.previewPlayhead()` are derived from `tick()` (`state/playback.ts`) and do not fire while the value stays the same. Canvases (timeline, piano roll, steps, automation, sample editor) read these, not `tick()`: the tick always arrives ~30 times per second (meters are live), and redrawing on every tick would redraw everything even with the player stopped. The timeline cursor is a separate element with `translateX` (`Timeline.tsx`): the canvas is not redrawn during playback. It is moved by `session.smoothPlayhead()` (`state/playback.ts`): the backend reports the position ~30 times per second, and between ticks the pure `domain/playhead.ts` extrapolates it from the tempo on every screen frame (`requestAnimationFrame`, only while audio is playing); a slightly late tick does not move the cursor backwards, while seeking and looping are accepted (the cursor waits at the end of `tick.wrap` — the loop region or the song, see "Song loop" ([docs/features/song-loop.md](../../../docs/features/song-loop.md)) — until the jump arrives). A new canvas that needs the position takes it from here. The timeline and automation canvases are the size of the visible scroll window (`ui/common/scrollWindow.ts`), not the full length of the track: a 120-bar canvas on a retina screen is about 130 million pixels, and redrawing it slowed down the whole screen. Drawing is done in whole-timeline coordinates shifted by the window's left edge; the mouse is measured against the full-size wrapper (`surface`), so gestures know nothing about the window. A new long canvas inside a scroll area is built the same way. Meter levels with smooth decay, a peak-hold tick and a clip light are computed once for the whole app by `state/levels.ts` (`session.levels`): the track headers, the mixer and the graph read them.
