# `src/mock/` — the browser mock of the backend

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [audio-clip-editing](../../../docs/features/audio-clip-editing.md), [audio-export](../../../docs/features/audio-export.md), [automation](../../../docs/features/automation.md), [bounce](../../../docs/features/bounce.md), [channel-utility](../../../docs/features/channel-utility.md), [cue](../../../docs/features/cue.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-meter](../../../docs/features/master-meter.md), [master-visualizer](../../../docs/features/master-visualizer.md), [midi-controllers](../../../docs/features/midi-controllers.md), [note-edits](../../../docs/features/note-edits.md), [pdc](../../../docs/features/pdc.md), [preferences](../../../docs/features/preferences.md), [processing-graph](../../../docs/features/processing-graph.md), [recording](../../../docs/features/recording.md), [sends](../../../docs/features/sends.md), [sidechain](../../../docs/features/sidechain.md), [song-loop](../../../docs/features/song-loop.md), [templates-and-presets](../../../docs/features/templates-and-presets.md), [tempo-map](../../../docs/features/tempo-map.md), [virtual-stage](../../../docs/features/virtual-stage.md), [warping](../../../docs/features/warping.md).

When the interface runs in a browser (`npm run dev`, no Tauri), `composition.ts` picks `MockRpc`, `MockDialogs` and `MockShell` instead of the Tauri ones. `MockRpc` answers the RPC methods from an in-memory project: `world.ts` (state, catalog, history), a handler per area in `handlers/<area>.ts` with the backend's checks (simplified, as the header of `MockRpc.ts` says) and the same error codes, `meters.ts`, `liveSound.ts` (the sound of the master visualizer and the effect visuals, answered as bytes by `wire.ts` for `callBinary`), `MockRpc.ts` (assembly, the call, the `tick` stream and the project feed, which always sends the whole project).

**Failures** look exactly like the backend's: `errors.ts: fail(code, params)` builds the same `{ code, params, message }` with a code from the Rust registry (`crates/daw-contracts/src/codes/`) and its English template copied into the `ENGLISH` table, so the interface translates mock errors by code too. A new mock failure: find the backend code for the situation, copy its template into `ENGLISH`, `throw fail(...)`. A new method: the [add-operation](../../../.claude/skills/add-operation/SKILL.md) recipe.
