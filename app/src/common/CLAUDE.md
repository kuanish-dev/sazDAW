# `src/common/` — what several roles share

The UI kit and the small pure helpers more than one role uses. A piece used by one role belongs in that role's folder; it moves here when a second role needs it.

- **UI kit:** `Knob`, `Fader`, `PanKnob`, `MuteSolo`, `ChannelUtility`, `ParamControl`/`ParamMenu`, `PickSelect`, `Modal`, `ContextMenu`, `InlineRename`, `NumberField`, `BarsStepper`, `PresetBar`, `Toasts`, `Meter`, `icons.tsx` (inline SVG in `currentColor`; no icon fonts or packages) and the techniques `canvas.ts`, `pointer.ts`, `scrollWindow.ts`, `theme.ts: palette()`, `motion.ts`, `waves.ts`.
- **Pure helpers:** time and grid (`time.ts`), the tempo map (`tempoMap.ts`, the same math as `daw-contracts/src/tempo_map.rs`), pitch names (`pitch.ts`), `math.ts` (`clamp`), the small graphs' geometry (`plot.ts`), the knob scale (`knobScale.ts`), catalog lookups (`catalog.ts`), file paths and labels (`format.ts`), the part dialogs' number fields (`partFields.ts`), the shortcut help rows (`shortcuts.ts`).

Map of the whole code: [ARCHITECTURE.md](../../../ARCHITECTURE.md). Cross-layer features it takes part in: [audio-export](../../../docs/features/audio-export.md), [automation](../../../docs/features/automation.md), [bounce](../../../docs/features/bounce.md), [channel-utility](../../../docs/features/channel-utility.md), [cue](../../../docs/features/cue.md), [errors](../../../docs/features/errors.md), [markers-colors-folders](../../../docs/features/markers-colors-folders.md), [master-meter](../../../docs/features/master-meter.md), [master-visualizer](../../../docs/features/master-visualizer.md), [midi-controllers](../../../docs/features/midi-controllers.md), [note-edits](../../../docs/features/note-edits.md), [preferences](../../../docs/features/preferences.md), [processing-graph](../../../docs/features/processing-graph.md), [recording](../../../docs/features/recording.md), [sends](../../../docs/features/sends.md), [sidechain](../../../docs/features/sidechain.md), [song-loop](../../../docs/features/song-loop.md), [sounds](../../../docs/features/sounds.md), [templates-and-presets](../../../docs/features/templates-and-presets.md), [tempo-map](../../../docs/features/tempo-map.md), [virtual-stage](../../../docs/features/virtual-stage.md), [warping](../../../docs/features/warping.md).

**Look** (VS Code "Dark/Light Modern" style, described at the top of `src/index.css`): all colors are CSS variables in `src/index.css` (`@theme` for dark, `:root[data-theme="light"]` for light, `data-accent` rules for the accent); canvases read them through `common/theme.ts`. A new control uses the shared classes (`.btn` and its variants, `.field`, `.panel`, `.label`, `.section-header`, `.menu-item`) and color tokens (`text-on-accent`, `bg-select`, `bg-hover`…) instead of raw colors.

**Motion.** One short tempo for the whole app: the duration and easing tokens and the `.anim-*`/`.beat-*` classes are in `src/index.css` ("Motion"); a new animation reuses them. Keyframes move only `opacity`, `scale` and `translate`, and entrances fill `backwards` (why: the comment there). The system's "reduce motion" setting turns CSS motion off; loops driven from code check `common/motion.ts: prefersReducedMotion()`.

**Live visuals**: the timeline glow layer (`tracks/activityRender.ts`), the track header's level glow (`TrackHeader.tsx`), meters (ballistics `mixer/mixer.ts: stepMeter`, state `mixer/levels.ts`, picture `common/Meter.tsx`; readings that already fall at their source, like the input level, go through `plainLevel`), the beat lights and the Play button pulse (`transport/BeatLights.tsx: createBeat`), the welcome screen's waveforms (`shell/WelcomeBackdrop.tsx`) and the same waves in the transport bar, which swell and tremble with the master meter's peak (`transport/HeaderWaves.tsx`; both draw with `common/waves.ts: drawWaves`, `energy` 0 is the calm drift), the master visualizer ([docs/features/master-visualizer.md](../../../docs/features/master-visualizer.md)). A new per-frame drawing reads `smoothPlayhead` and keeps its per-frame work small, like the glow layer (its own transparent canvas, only the clips under the playhead) — never a heavy canvas.

**Large components are split by role**: the assembling component holds the view state, drawing goes to `*Render.ts`, mouse handling to `*Pointer.ts`/`pointer.ts`, geometry to `*Layout.ts`. The assemblies, each listing its parts in its header: `pianoroll/PianoRoll.tsx`, `graph/GraphView.tsx`, `samples/SampleEditorView.tsx`, `automation/PatternEditor.tsx` (with `AutomationClipPanel`), `drums/DrumPartDialog.tsx`. The backend mock is organized the same way ([src/mock/CLAUDE.md](../mock/CLAUDE.md)).

**Shared techniques go into `common/`**, not copied into a role (a canvas matched to screen density, the mouse point, a theme color) — as did the selection box (`canvas.ts: drawSelectionBox`), the visible-window test (`scrollWindow.ts: inWindow`), the bars stepper (`BarsStepper`), the looping audition of the drum and chord part dialogs (`loopPreview.ts`) and track colors (`trackColors.ts: trackColorOf`/`clipColorOf`).

**Long canvases** inside a scroll area (the timeline rows, the ruler strip and automation lanes) are only the size of the visible window (`common/scrollWindow.ts`; why: its header). Drawing is in whole-timeline coordinates shifted by the window's left edge; the mouse is measured against the full-size wrapper (`surface`), so gestures know nothing about the window. A new long canvas is built the same way.
