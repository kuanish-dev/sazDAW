# `daw-patterns`

**Parts from patterns**: `PatternBank` (`PatternLibrary`: ready-made drum patterns — grooves, fills, breaks, intros, endings; the table is in `data.rs`), `DrumPartBuilder` (`DrumPartControl`: turns a sequence of patterns into drum tracks and clips with notes in a single undo step) and `DrumPartPreviewer`; `ChordPartBuilder` (`ChordPartControl`: a chord progression strummed on one track) and `ChordPartPreviewer` (see "Chord parts"); `render.rs` renders and loops both previews.

Depends on: contracts.

Map of the whole code: [ARCHITECTURE.md](../../ARCHITECTURE.md). Cross-layer features it takes part in: [tempo-map](../../docs/features/tempo-map.md).

## Drum patterns (`daw-patterns`)

A pattern is a drawing on a 16th-note grid, one row per drum: `X` accent, `x` normal, `o` soft, `.` rest (`"X... .... X... ...."`). Roles: `groove` (the main rhythm), `fill` (a full bar, placed as the last bar of a phrase), `break` (a stop/drop), `intro`, `ending`. A pattern is 1 or 2 bars; `data.rs` has ~50 of them. A new pattern = a new entry in the `PATTERNS` table; the `every_builtin_pattern_is_valid` test checks grid lengths, drums, and duplicates.

**A part** = `DrumPartRequest { startBar, slots: [{ pattern, repeat }], replace }`: patterns are placed one after another starting at `startBar` (zero-based bars). `DrumPartBuilder::build` validates everything up front (patterns, drums, occupied space) and then builds in a single undo group (`begin_group`/`end_group`); on a failure midway it rolls the group back. Each drum gets one track of the right kind: an existing one (the topmost) or a newly created one (names in `createdTracks`); each pattern and drum gets one note clip `bars × repeat` bars long, whose content is a single pattern (`loop_ticks` is fixed), so repeats loop inside the clip, and editing one drawing changes all repeats. Notes follow General MIDI (kick 36, snare 38…), so MIDI export looks familiar. Occupied space: `replace: false` — rejected with an error, `true` — the drum clips in that range are deleted.

**Your own sounds.** A pattern only says "kick, snare, hi-hat…" — what plays them is decided by the request: `lanes: [{ lane, target }]` (drums without an entry are `auto`). `target`: `auto` — a built-in drum (your track of the same kind is used if there is one, otherwise one is created); `skip` — the drum does not play; `{ type: "track", id, pitch? }` — your track (notes at pitch `pitch`, by default the track's step-input pitch; for a sampler that is the root note, so the sound plays unshifted); `{ type: "sample", id }` — your sample from the project: a sampler track "Kick: sample name" is created. Several drums can be sent to one track — their hits merge into one clip (coinciding notes of the same pitch become one, louder). Everything is validated before any edits: an unknown drum, an audio track instead of an instrument track, a nonexistent track or sample — rejected without leaving traces. The sound choices in the dialog are remembered between builds (`session.drumKit`); a choice that no longer exists is treated as `auto`. Example: `drums.build { "slots": [{"pattern":"rock_basic","repeat":4}], "lanes": [{"lane":"kick","target":{"type":"track","id":5}}, {"lane":"snare","target":{"type":"sample","id":2}}, {"lane":"crash","target":{"type":"skip"}}] }`.

**Preview.** `DrumPartPreviewer` (`DrumPartPreview`) plays a part WITHOUT changing the project: the same patterns and the same drum sounds (`lanes`) that a build would produce are rendered once into a temporary 48 kHz stereo buffer (one instrument per track/drum, created through `InstrumentCatalog`, at the project tempo), cymbal tails are wrapped around to the start of the loop, and the buffer goes to the engine's existing preview voice (`DspCommand::PreviewPlay`, looped) — no engine changes were needed. It plays until `stop` is called; a new `play` replaces the previous one; at most 16 bars. The "drum → sound" choice is resolved by the shared `LaneKit` (`kit.rs`), which the part build also uses, so what you hear matches what will be built.

RPC: `patterns.list` (`{ style?, role? }`, patterns with grids as strings), `patterns.get { id }`, `drums.build`, `drums.preview` (the same request as `build`), `drums.stopPreview`. UI: the "🥁 Drum part" button above the timeline (in the dialog each pattern has "▶ Listen" and there is "▶ Preview part" — looped until you press "■ Stop"; closing the dialog stops the sound) (`ui/drums/DrumPartDialog.tsx`), actions `session.actions.drums.*`. Example for AI: `drums.build { "slots": [{"pattern":"intro_crash_start"},{"pattern":"rock_basic","repeat":6},{"pattern":"fill_tom_cascade"},{"pattern":"rock_drive","repeat":7},{"pattern":"fill_snare_roll"},{"pattern":"ending_crash_stop"}] }`. The browser mock (`mock/handlers/drums.ts`) knows only 8 patterns and builds a part with separate edits rather than one undo step.

## Chord parts (`daw-patterns`: `chord_part.rs`, `strum.rs`, `voicing.rs`)

A chord progression strummed on one instrument track. **Contract** (`daw-contracts/src/chord_part.rs`): `ChordPartRequest { target, startBar, strum, bars, repeat, replace }` — `target` is `{ "type": "track", id }` or a new track `{ "type": "new", kind }` (named after the kind's label); `bars` holds one or two chord **symbols** per bar (`[["C"], ["G"], ["Am", "F"]]`; the second chord starts in the middle of the bar), read by `Chord::parse`: a root C…B with an optional `#`/`b`, then `""`, `m`, `7`, `maj7`, `m7`, `sus2`, `sus4`, `dim`, `aug`. **Strums** (`STRUMS`, data in the contract like `TRACK_COLORS`): one 4/4 bar of eighth notes — `D` down, `U` up, `X` a muted down stroke (a "chuck"), lower case softer, `.` nothing; `four` `D.U.X.U.`, `six` `D.DU.UDU`, `eight` `DUXUDUXU` — the "бой четвёрка / шестёрка / восьмёрка" of the Russian guitar tradition. Like drum patterns they are not reshaped for another meter.

* **How the instrument plays** (`voicing.rs`, by the target's instrument kind): the guitars (`GUITAR_KIND`, `ELECTRIC_GUITAR_KIND`: E2–E4 standard tuning, the same shapes) and the ukulele (`UKULELE_KIND`, re-entrant G4 C4 E4 A4) voice the chord like a player — one note per string, an open string where it is a chord tone, a fretted one within one hand position (four frets), positions up to the 7th scored by: all chord tones, more strings, open strings, a lower position; the guitar's lowest note is the root (C = x32010, D = xx0232, G7 = 320001). The bass (`BASS_GUITAR_KIND`) plays the root from E1 up an octave, on down strokes only. Any other instrument plays a block chord from C3.
* **Strumming** (`strum.rs`): a down stroke runs over the strings from the first to the last, an up stroke back over the top four, each string 12 ms later (`spread_ticks`, at the part's starting tempo, at most 1/12 of a step) and 3 velocity steps softer; the bar's first stroke is accented. A string rings until a stroke hits it again, the chord changes, or a muted stroke stops every string (its own notes are 1/8 of a step: the strings damp them at once). Everything ends with the progression; the clip's content is one pass (`loop_ticks`), so repeats loop inside it and editing one pass changes all.
* **Build** (`ChordPartBuilder`): `chord_part::plan` checks everything first (the strum `PT-074`, no bars `PT-174`, too many `PT-275`, one or two chords per bar `PT-175`, symbols `PT-103`, repeats `PT-271`, the track `TR-001`/audio `PT-176`/kind `TR-002`, the start bar `PT-272`) and works out the notes; occupied space is `PT-370` or replaced; then one undo group ("Chord part"): the new track, the removed clips, one note clip; a failure rolls the group back. **Preview** (`ChordPartPreviewer`): the same plan, every repeat, played by the target's instrument (a new kind with its defaults) into a buffer and looped by `render.rs` (shared with the drum preview); at most 16 bars (`PT-274`).
* **RPC:** `chords.strums`, `chords.build`, `chords.preview`, `chords.stopPreview`; the MCP instructions mention the workflow. **UI:** "🎸 Chord part" above the timeline (`ui/chords/ChordPartDialog.tsx`): the progression as bars (`ProgressionBars`: select a chord, split a bar in two with ½, add and remove bars), the key's own chords and any root + type (`ChordPalette`; until edited, the starting I–V–vi–IV / i–VI–III–VII follows the key), the rhythm (`StrumPicker`, arrows from `domain/chordPart.ts: strumArrows`), the track (a new acoustic or electric guitar, ukulele or bass, or yours), start, repeats, replace; "▶ Listen" loops the part and plays it anew after every edit. Pure logic — `domain/chordPart.ts`; actions — `session.actions.chords.*`. The browser mock (`mock/handlers/chords.ts`) writes block chords from C3 on every stroke with separate edits.
* **Tests:** symbols and strums — `daw-contracts/src/chord_part.rs`; voicings (the open shapes, every chord on every instrument) — `voicing.rs`; strokes, ringing, chucks, chord changes, the bass — `strum.rs`; one undo step, voicing on a real session, occupied space, refusals, preview and playback — `daw-bootstrap/tests/all/chord_part.rs`; wire — `daw-rpc/tests/all/chords.rs`.
* **A new strum:** a row in `STRUMS` (and the mock's `STRUM_GRIDS`). **A new string instrument:** its kind in `daw-strings` and a tuning row in `voicing.rs: style`.
