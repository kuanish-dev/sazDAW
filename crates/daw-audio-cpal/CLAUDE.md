# `daw-audio-cpal`

Audio via cpal: `CpalAudio` (`AudioDevices`) — device list, choice of output/input and buffer size, stream restart, input level, input capture (`AudioCapture`), input for monitoring (`LiveInput`, `live.rs`).

Depends on: contracts.

Map of the whole code: [ARCHITECTURE.md](../../ARCHITECTURE.md). Cross-layer features it takes part in: [recording](../../docs/features/recording.md).

## Audio: devices and buffer

**Contracts** (`daw-contracts/src/audio.rs`): `AudioDevices` (devices, selection, status, `apply`, `watch_input`, `input_level`) and `AudioSettingsStore` (where the selection is stored). The UI sees them only as `Controls.audio` and the `audio.*` RPC (`daw-rpc/src/audio.rs`).

- **`CpalAudio`** (`daw-audio-cpal`) is the only one that knows about cpal. A cpal stream cannot be moved between threads, so `CpalAudio` starts a **host thread** (`host/`: `mod.rs` — commands, the loop and the shared state `Shared`, `output.rs` — output, `input.rs` — input and capture, `faults.rs` — stream faults): all output and input streams are created, live and are closed in it, and the rest of the code sends it commands (`Start` / `Apply` / `WatchInput` / `Outputs` / `Inputs` / `Stop`) and waits for the reply over a channel. Status, selection and peaks are read directly from the shared state (`Shared` methods, fields hidden), without going through the thread. Starting and stopping output — `CpalAudio::start_output/stop_output` (not to be confused with `AudioCapture::start/stop`). The system audio is hidden behind a small private trait `Backend` (`backend.rs`; the real one is `system.rs`), so the host thread is tested with fake "hardware" without a sound card. Pure rules (choosing by name, valid buffer) — `choose.rs`, peaks — `peaks.rs`.
- **Stream restart.** The engine lives in an `Arc<Mutex<Box<dyn AudioRenderer>>>` outside the output stream. Changing the device or buffer: validate the selection (the device exists, the buffer is within `buffer_range`) while the old sound is still playing → close the old stream → open the new one → `renderer.prepare(new StreamConfig)` before `play()` (sample rate and channel count may change). In the callback the engine is taken via `try_lock`: while the lock is held (only at the moment of the switch) the block is silent — waiting and allocating are not allowed. If the stream fails to open, sound goes back to the previous device, otherwise to the system default; `apply` returns an error and does not save the selection.
- **Startup.** `Session::start_audio()` (`daw-bootstrap`) starts the host with the saved selection; a missing device means starting on the system default + a warning in `AppLog` (source `audio`), not a crash. cpal stream faults are written to `AppLog` and to `status.error`. The cpal error callback can arrive from the audio thread (on macOS — overloads and render failures), so it only counts faults in atomics (`faults.rs`, `StreamFaults`), and the host thread moves them into the log and status (it wakes every 250 ms; overloads — at most once every 5 s, with their count). Test builds (`build_session`) get `CpalAudio::without_devices`: lists are empty, there is nothing to open, the selection is saved.
- **Input is opened only on request** (`watch_input(true)`) and closed on `false`: otherwise macOS would ask for microphone access at startup. In the input callback, peaks of the first two channels (for mono both are equal) are computed into atomics; peak decay happens on the reading side. The audio recording status shows these same peaks (`AudioDevices::input_level`). A denied permission is returned as an error with a hint about the microphone permission; a built `.app` needs the `NSMicrophoneUsageDescription` key (`app/src-tauri/Info.plist`).
- **The `audio.json` file** (`AudioSettingsFile` in `daw-persistence`, next to `recent.json`): `{ output, input, bufferFrames, recordLatencyMs }` (the last one is optional, ms), writes are atomic, a corrupted file means the default selection.
- **Input capture** (`AudioCapture`, `daw-audio-cpal/src/capture.rs`). A single input stream serves both the level meter and recording; it stays open as long as at least one consumer needs it (`watch_input` or capture, a counter in the host thread). In the input callback: peaks and, while capture is on, copying the first two channels into a preallocated `rtrb` ring buffer (~5 seconds at the real stream's sample rate and channel count); no allocations, no locks, only atomics. Frames that don't fit (whole frames) are counted in `dropped_frames` and logged when the take stops. The queue is SPSC: the producer is the callback, the consumer sits under a `Mutex` in `Shared` and is read in `drain` from a regular thread (the remainder is available after `stop` too). The format (`StreamConfig`) is the stream's, 1–2 channels. Changing the input device during recording is rejected. Without hardware (`without_devices`, `build_session`) `start` returns an error.
- **`AudioRecorder`** (`daw-audio-recorder`): recording is armed per track (`set_armed`, `set_input`; more in "Input monitoring, multitrack recording and takes" ([docs/features/recording.md](../../docs/features/recording.md))). `start()` takes the armed audio tracks, checks that the project has a file, opens capture, starts the transport (if it was stopped; only in that case will it stop it at the end) and spawns a thread that every ~20 ms pulls frames and updates the status (seconds, peaks, drops). `stop()` pulls the remainder, trims the latency, hands the tracks their channels and writes a WAV for each (`AssetStore::new_asset_path`, name "Recording <track>"), imports the sample and creates a clip at the start bar (or a new take of a covered clip; with a loop region, one take per loop pass — see "Loop recording" ([docs/features/recording.md](../../docs/features/recording.md))). **One undo step** — `HistoryControl::begin_group/end_group` around the files, import and clips of all tracks; a failure on one track does not undo the others, and the error lists the failures. Placement rules (overlap, length by tempo) are checked by `ClipControl::add_audio_clip` itself; on rejection the sample stays in the project, no clip is created, and the error reads "audio recorded to "Samples", but the clip was not created: <reason>". An empty take is an error; the project is not changed.
- **Recording latency.** Sound from the input arrives later than the program played it: by the input buffer, the output buffer and the interface. `latency_ms = AudioSettings::record_latency_ms`, and if it is `None` — the estimate `2 × buffer_frames (otherwise 512) / output sample rate`; in frames — at the input sample rate. The first `latency_frames` frames are trimmed before writing the WAV (`ClipEdit` cannot change `offset_frames`, and the clip starts at the start bar anyway); the clip length is taken from the remaining frames. A take shorter than the latency is an error. The exact value is tuned by ear and entered in the audio settings.
- **Memory.** Audio accumulates in a `Vec<f32>` up to the `Deps::max_samples` limit (~20 minutes of stereo at 48 kHz, about 460 MB); memory is grown in 10-second chunks rather than by doubling. When the limit is reached: capture and the transport we started are stopped, an error is logged, `status.recording` becomes `false` while `track != null` (the UI sees "waiting for stop"), and the accumulated audio is saved on `stop()`.
- RPC: `audioRecord.setArmed { track, armed }`, `audioRecord.setInput { track, input: "stereo"|"left"|"right" }`, `audioRecord.start`, `audioRecord.stop` → clips, `audioRecord.status` → `{ recording, full, seconds, left, right, droppedFrames, tracks: [{ track, armed, input, left, right }], monitorProblem }`; `tracks.setMonitor { track, mode }`; `clips.setActiveTake { id, take }`, `clips.removeTake { id, take }`; `audio.devices` returns the device channel count (`channels`); `audio.settings` / `audio.apply` carry `recordLatencyMs`.
- Adding a similar setting: a field in `AudioSettings` → file → `CpalAudio::apply` → RPC.
