# `daw-engine`

Real-time audio engine: playback of tracks' note and audio clips, graph processing in topological order from the snapshot (sources → effects and buses in any order → master), sidechain, automation, meters, the master scope for the visualizer, the node tap for the effect visuals and the meter tap for the live loudness meter (`scope.rs`), the mono check on the output (see "Live master meter" ([docs/features/master-meter.md](../../docs/features/master-meter.md))), the channel utility (`mixer/utility.rs`: polarity, width, mono, fine time alignment, see "Channel utility" ([docs/features/channel-utility.md](../../docs/features/channel-utility.md))), the virtual stage (`stage/`: a channel's place in the shared room, its direction cue — a parametric HRTF on headphones — and the room's tail, see "Virtual stage" ([docs/features/virtual-stage.md](../../docs/features/virtual-stage.md))).

Depends on: contracts.

Map of the whole code: [ARCHITECTURE.md](../../ARCHITECTURE.md). Cross-layer features it takes part in: [audio-clip-editing](../../docs/features/audio-clip-editing.md), [automation](../../docs/features/automation.md), [channel-utility](../../docs/features/channel-utility.md), [master-meter](../../docs/features/master-meter.md), [master-visualizer](../../docs/features/master-visualizer.md), [midi-controllers](../../docs/features/midi-controllers.md), [pdc](../../docs/features/pdc.md), [processing-graph](../../docs/features/processing-graph.md), [recording](../../docs/features/recording.md), [sends](../../docs/features/sends.md), [sidechain](../../docs/features/sidechain.md), [virtual-stage](../../docs/features/virtual-stage.md), [warping](../../docs/features/warping.md).

## Code layout

Where to look for what: the engine is `daw-engine/src/`: `engine.rs` (audio thread: the segment conductor), `link/` (`mod.rs` — `EngineLink`: snapshots and the "graveyard", DSP commands and the `Garbage` release queue with its audio-side end `GarbageBin`, live notes and recording; `telemetry.rs` — format, load, preview position, latency, `Loss` drop counters, and the scopes (`EngineStats`, `NodeScope`, `MasterTap`); the mono check's switch (`MonoCheck`); `monitor.rs` — the input table; `held.rs` — lanes held by live automation writing), `meters.rs` (`Meters`: level meter cells), `scope.rs` (`Lane`s of atomics behind `MasterScope`, the master window for the visualizer, and `NodeTap`, the watched node's input and output windows that the mixer feeds; `MeterTap`, every stereo master frame for the live meter, numbered so its reader can tell what it missed), `instruments.rs` (`InstrumentRack`: track instruments), `playback.rs` (what to play: `notes.rs` — note schedule, `controllers.rs` — controller schedule and chase, `audio_voices.rs` — audio clip voices), `automation.rs` (`AutomationPlayer`), `params.rs` (which parameters to re-send), `preview.rs`. The mixer is `mixer/`: `mod.rs` (node tables, buffers, `process`), `effects.rs` (`EffectPool`: the effect store), `compile.rs` (graph snapshot → tables: nodes, edges, order, audibility under solo, effects, meters, channel utility slots; nodes are looked up by binary search) (also where volume and pan are overridden by automation for the segment), `utility.rs` (the channel utility: polarity, width, mono, fine time alignment), `latency.rs` + `delay.rs` (plugin delay compensation, see "Plugin delay compensation (PDC)" ([docs/features/pdc.md](../../docs/features/pdc.md))). On a new snapshot, DSP objects receive only the parameters that changed (a new object gets all of them; after `prepare` and at the end of automation — all of them); preview commands do not touch parameters. `EngineLink::send` prepares (`prepare`) an instrument or effect before sending it to the queue; the mixer on the audio thread prepares nothing. The frame of an event within a segment is a single formula, `BlockTiming::frame_at`, for notes, audio clips and the metronome.

## Releasing memory on the audio thread

Releasing memory on the audio thread: everything the audio thread might release as the last owner (an instrument, an effect, a preview sound and an audio clip voice's sound) goes into the `Garbage` queue (`GarbageBin::throw`), and the control side releases it explicitly with `DspSink::collect_garbage`: when sending a command, in the `daw-engine-watch` watchdog thread (`daw-bootstrap/src/engine_watch.rs`, ~20 Hz) — so the queue does not overflow during long playback without edits — and in offline export on every chunk. The same thread logs (`source: "engine"`) every increase of `EngineStats::losses`: live notes and recording notes that did not fit into the queues, and "leaked" objects. Audio clip voices hand their sound to the same queue when they are dropped (end of the sound, stop, seek, change of the processed sound); a voice past the end of the sound is never started at all. A queue overflow is a leaked reference (counted in `EngineLosses::leaked_garbage`), not a release on the audio thread.
